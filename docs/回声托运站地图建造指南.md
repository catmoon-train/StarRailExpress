# 回声托运站地图建造指南

> 适用对象：服主 / 地图作者 / OP（命令均需权限等级 2）。
> 模式 ID：`noellesroles:echo_freight`；地图配置目录：`<世界根目录>/echo_freight/maps/`。

## 1. 模式概览

回声托运站是 6–32 人的货运对抗模式：**托运者**采集晶体、启动信标并撤离；**截流者**污染信标、封锁核心门；**投机客**持有私人契约各自为战。

### 1.1 人数档（`EchoRosterPolicy`，按实际到场人数自动定）

| 人数 | 截流者 | 投机客 | 托运者 | 信标总数 | 撤离配额 | 行动时长 | 撤离窗口 |
|---|---|---|---|---|---|---|---|
| 6–7 | 1 | 1 | 4–5 | 2（含 1 核心） | 3 | 720 秒 | 90 秒 |
| 8 | 1 | 1 | 6 | 3（含 1 核心） | 4 | 720 秒 | 90 秒 |
| 9–11 | 2 | 1 | 6–8 | 3（含 1 核心） | 4–5 | 840 秒 | 120 秒 |
| 12 | 2 | 2 | 8 | 3（含 1 核心） | 5 | 840 秒 | 120 秒 |
| 24 | 4 | 4 | 16 | 3（含 1 核心） | 10 | 840 秒 | 120 秒 |
| 32 | 6 | 5 | 21 | 3（含 1 核心） | 14 | 840 秒 | 120 秒 |

> 6–12 人保留原规则：6–7 人撤离配额 3，8–9 人 4，10–12 人 5；13–32 人按 `EchoRosterPolicy` 比例扩展，信标仍为 3 座，晶簇/物资箱最低数量不翻倍。保存、校验和绑定检查 **6 人至该图出生点容量上限**的全部人数档（最多 32）；旧 8/2/2 或 16/4/4 出生点图仍可保存、绑定并供原容量内人数开局，不能供 32 人开局。

### 1.2 地图的两大空间

```
开放区（出生、采集、大部分交互）
┌───────────────────────────────┐
│  [托运出生][晶簇][祭坛][黑晶]   │
│                             ┌─┴──┐ ← 核心门（实心方块封死，局内开关）
│  [截流出生]                 │核心│   core_area 框选的封闭区域
│                             │区  │
│  [撤离区]──撤离门           │·核心信标（全图唯一）
│                             │·黑市箱  │
│                             │·免费出口│
│                             └─┬──┘   控制点（在区内）
│                          free_safe（区外安全点）
└───────────────────────────────┘
```

- **核心区（coreArea）**：用两角框选的封闭区域，相当于主控室/金库；
- **核心门**：核心区墙上的开口，制图时用实心方块填满，局内开门时替换为空气、关门还原；
- **撤离区**：撤离阶段的存活判定区。

## 2. 建造前准备

### 2.1 工具

| 工具 | 获取方式 | 用途 |
|---|---|---|
| 回声地图编辑仪 | 创造模式物品栏 → **「回声托运站」**分类（管理员） | 图形化制图（推荐） |
| `/sre:echo map ...` 命令 | OP2，控制台或聊天栏 | 命令流制图（与编辑器同一套底层） |
| Areas 地图工具 | `/tmm:switchmap load <地图>` | 把实战地图加载进世界（拿模板/粘贴偏移） |

> 编辑器工具**自包含**：不加载 Areas 地图也能新建、标记、保存（坐标按世界原样记录）；
> 但推荐先加载实战地图，这样坐标会按该图的模板/粘贴偏移换算后存盘，与开局预检完全一致。

### 2.2 开发模式开关

目前模式处于开发阶段，开局必须带 JVM 参数：

```
-Dsre.echo.development=true
```

### 2.3 硬性前提

- 地图（`train_maps/<name>.json`）已存在于 `<世界根目录>/train_maps/`；
- 开局人数 6–32 人，且各阵营出生点必须足够实际人数；
- 地图 `gameModes` 必须显式包含 `echo_freight`（见[第 9 节](#9-第七步启用为回声地图并开局)）。

## 3. 第一步：搭建地图建筑

### 3.1 建筑要求总表

| 位置 | 方块要求 | 说明 |
|---|---|---|
| 所有目标点所在格 | **非空气方块**，ID 不限 | 玩家空手右键该格触发交互；建议避开箱子/熔炉等带 GUI 的方块 |
| 门体积内每一格 | **无方块实体、完整碰撞、实心的普通整方块** | 局内会被替换成空气再还原；不能用门、活板门、台阶、楼梯、半砖、栏杆、玻璃板、地毯、拉杆/按钮，不能用箱子/信标等带 BE 的方块，不能有流体 |
| 出生点脚下 | 1 格完整实心方块 | 脚 + 头顶共 2 格必须是无碰撞空气 |
| 出生点周围 | 无流体、无危险方块 | 危险方块：火、岩浆块、营火、灵魂营火、仙人掌、甜浆果丛、凋零玫瑰、细雪 |

### 3.2 空间划分

- **开放区**：出生点、晶簇点、祭坛、黑晶点/投放点、物资箱、各控制点、投机客出口、撤离区都在这里；
- **核心区**：只放三样——**核心信标（恰好 1 座）**、**黑市箱**、**免费出口控制点**；
- **核心门**：至少 2 扇，先标 `core_control` 控制点，再用两角框出门体；
- **撤离门 + 撤离检测区**：各 1 个，互不重叠，也不与核心门重叠。

### 3.3 坐标是怎么存的

- 你站在实战区照常瞄准/走动，编辑器/命令自动把**世界坐标**换算成**模板坐标**存盘（用当前 Areas 地图的模板区→粘贴区偏移）；
- 没加载 Areas 地图时按世界坐标原样记录（保存消息会提示，之后加载地图重新载入校对即可）；
- 开局预检再把模板坐标平移回实战区，**不需要自己算任何偏移**。

### 3.4 用代码生成测试地图「回声枢纽」（一键）

没有现成建筑时，可以用生成器把一张**完整可玩的 200×200 测试地图**写进当前 Areas 地图的模板区，
不用手工摆方块、也不用逐个标记点位：

```text
/sre:echo map generate season1/echo_hub     # 生成（需要当前已加载 Areas 地图）
/sre:echo map generate status               # 查看阶段/进度
/sre:echo map generate cancel               # 取消（已写入的方块保留）
```

**前提**（不满足会直接报错并给出实际尺寸）：

- 已用 Areas 工具加载一张地图，`resetTemplateArea` 至少 **200×22×200**（X×Y×Z，含两端方块）；
- 模板区与粘贴区是纯平移（偏移为整数方块），生成器不会自己加第二次偏移；
- 非对局状态（`INACTIVE`）才能执行。

**它做五件事**，每 tick 只推进一小片，不会卡主线程：

1. 加载模板区块并统计会被覆盖的旧方块；超过 64 格要求再执行一次带 `confirm` 的同名命令；
2. 按布局整块覆盖模板区（空气也写，避免残留旧地形），写块只带
   `UPDATE_CLIENTS|UPDATE_KNOWN_SHAPE`，不触发邻居更新，没有流体/重力/红石级联；
3. 把模板区整块复制到实战区，生成完就能走图；
4. 写 `<world>/echo_freight/maps/<mapId>.json`、绑定生效地图、补齐 Areas 设置
   （清初始物品/会议/场景任务/强制职业，声明 `echo_freight`）并保存地图配置；
5. 跑 6–32 人预检，再复用开局路线准入的四阶段步行检查，直接给出
   「关门进不去核心 / 两扇核心门都能进核心 / 撤离门开时到得了撤离区」的结论。

**分区布局**（200×200，全部整格方块、无方块实体）：

| 区域 | 位置（局部坐标） | 内容 |
|---|---|---|
| 外围假山带 | 四边各 5 格 | 6–13 格高的环状山体，把整张图围死，走不到模板外虚空 |
| 北院货场 | x 30..170，z 8..54 | 混凝土硬地、集装箱堆、龙门吊、货运棚、6 个截流者出生点 |
| 西侧工业区 | x 14..58，z 64..148 | 金属硬地、4 座厂房、烟囱、料仓、管线 |
| 东侧仓储市场 | x 142..186，z 64..148 | 木地板、4 座仓库、两排摊位、货堆 |
| 核心枢纽 | x 84..116，z 58..86 | 大厅 + 金库（核心信标、2 黑市箱、内部免费出口），东西两扇铁门 + 墙上控制台 |
| 南侧托运者营地 | x 40..146，z 150..192 | 草地、7 座帐篷、21 个托运者出生点、营地灯 |
| 撤离门楼 | x 150..182，z 152..178 | 西门 + 门后封闭检测区、门外安全点与掉货锚点 |
| 中央枢纽广场 | 圆心 (100,100) 半径 20 | 所有道路的汇合点，3 座祭坛在广场与南侧 |
| 台地 | 四角各一块 | 抬升 1 格的观景台/月台，不承担连通性 |
| 假山群 | 15 处散布 | 填补空白并分隔分区，被道路切出通道 |

**道路**：全部用整数坐标折线 + 圆形印章铺设（主脊宽 4 格、支线宽 3 格），
转角处印章自然重叠，不会出现 1 格断缝；没有任何一条是笔直长线。

**地形不平坦**：台地抬 1 格、假山 4–13 格、外围山脊 6–13 格；
但**所有点位、出生点、门体、撤离区都落在同一脚层（y=4）**，
所以 `canJump=false` 时开局路线依然走得通，台地和假山只做视觉起伏。

点位数量固定为：托运者出生 21、截流者出生 6、投机客出生 5、信标 3（1 核心 + 2 开放）、
晶簇 6、祭坛 3、普通物资箱 10、黑市箱 2、黑晶点 2、投放点 2、核心门 2。

生成成功后按第 9 节开局即可；重复执行会原子覆盖同一个 `mapId` 的侧文件。

## 4. 第二步：用 Areas 工具加载实战地图

```text
/tmm:switchmap load <地图名>
```

- 地图名 = `train_maps/` 下的文件名（不含 `.json`），支持子目录如 `season1/echo_station`；
- 加载成功后会提示当前地图信息；回声侧文件此时还不会自动生效，见第 9 节；
- 可以用 `/sre:echo switchmap` 随时查看当前生效的回声地图与绑定状态。

## 5. 第三步：新建地图配置

### 5.1 用编辑器（推荐）

1. 手持**回声地图编辑仪**右键打开；
2. 「地图配置」页 → 地图 ID 框填写名字（**留空则自动取名** `echo_map`、`echo_map_2`…）；
3. 点 **「新建地图配置」**（从空白开始）或 **「载入地图配置」**（读取已保存文件继续改）；
4. 顶部状态行会显示：`配置 <id>｜修订 N｜文件：已保存/未保存｜生效：生效中/未生效｜本地图：已/未启用为回声地图`。

### 5.2 用命令

```text
/sre:echo map new echo_depot      # 新建空白草稿
/sre:echo map edit echo_depot     # 读取已保存文件进草稿
/sre:echo map cancel              # 丢弃内存草稿（不动文件）
/sre:echo map list                # 查看草稿摘要
```

### 5.3 草稿规则

- 每人同时 1 份草稿，全服上限 16 份；
- **内存态**：断线、切维度、模板偏移变化或闲置 30 分钟自动失效；
- 所有修改只在内存，**保存后**才写文件并影响下一局。

### 5.4 地图 ID 命名规则

- 1–64 位小写字母、数字、下划线、连字符（如 `echo_depot`、`station-a`）；
- 文件名 = `<mapId>.json`，支持子目录（`season1/echo_station` → `echo_freight/maps/season1/echo_station.json`）；
- **文件名必须与 Areas 地图名一致**（或改用 `/sre:echo switchmap load <mapId>` 绑定），否则开局预检找不到侧文件。

## 6. 第四步：标记坐标点位（19 种）

### 6.1 两种取点方式

| 方式 | 适用类型 | 说明 |
|---|---|---|
| **准星瞄准** | 方块类（信标/晶簇/祭坛/物资箱/黑晶/各控制点/出口） | 准星对着 16 格内已加载的方块，记录方块中心点 |
| **站脚位置** | 出生点类（`carrier_spawn`/`interceptor_spawn`/`broker_spawn`/`spectator`/`free_safe`/`evacuation_safe`/`drop_anchor`） | 直接取你站立的位置（含朝向） |

### 6.2 点位类型全表

| kind | 中文名 | 数量 / 规则 | 取点 | 人数档 |
|---|---|---|---|---|
| `carrier_spawn` | 托运者出生点 | 旧图 ≥8；支持 32 人需 ≥21，id 必须是 **0 起的连续下标** | 脚下 | — |
| `interceptor_spawn` | 截流者出生点 | 旧图 ≥2；支持 32 人需 ≥6，连续下标；离托运/投机出生点 ≥24 格 | 脚下 | — |
| `broker_spawn` | 投机客出生点 | 旧图 ≥2；支持 32 人需 ≥5，连续下标；所有阵营出生点不得互相重叠 | 脚下 | — |
| `spectator` | 观战出生点 | 全图 1 个 | 脚下 | — |
| `beacon_open` | 开放区信标 | 按人数档（≤7 人 2 座 / 8+ 人 3 座），两两相距 ≥24，必须在开放区 | 准星 | 有 |
| `beacon_core` | 核心区信标 | **恰好 1 座**，必须在核心区内 | 准星 | 有 |
| `crystal` | 晶簇点 | 生效数量 ≥4（≤7 人）/ ≥6（8+ 人） | 准星 | 有 |
| `altar` | 祭坛（钥匙刷新点） | **恰好 3 个**，两两相距 ≥20 | 准星 | — |
| `supply` | 普通物资箱 | 生效数量 ≥6（≤7 人）/ 8（8 人）/ 10（9+ 人），可重复刷新 | 准星 | 有 |
| `black_market` | 黑市箱 | ≥2，**必须在核心区内**，每局一次性 | 准星 | 有 |
| `black_node` | 黑晶采集点 | ≥2 | 准星 | — |
| `black_dropoff` | 黑晶投放点 | ≥2 | 准星 | — |
| `broker_exit` | 投机客出口 | 1 个 | 准星 | — |
| `core_control` | 核心门控制点 | ≥2（几扇门几个），与 `core_door` 体积同 id 配对 | 准星 | — |
| `free_control` | 免费出口控制点 | 1 个，**必须在核心区内** | 准星 | — |
| `free_safe` | 免费出口安全点 | 1 个，在核心区外 | 脚下 | — |
| `evacuation_control` | 撤离控制点 | 1 个 | 准星 | — |
| `evacuation_safe` | 撤离安全点 | 1 个 | 脚下 | — |
| `drop_anchor` | 撤离掉落锚点 | 1 个 | 准星 | — |

> **区域红线**：核心区内只能有 `beacon_core`、`black_market`、`free_control`；
> 出生点、晶簇、祭坛、黑晶点/投放点、投机客出口、`free_safe`、`evacuation_safe`、`drop_anchor`、`beacon_open`
> 以及所有开放区点位都**不能**落在核心区、门体积或撤离区里。

### 6.3 「人数」是什么意思

**人数 = 启用人数档（minPlayers，6–32，默认 6）**：只有**大于等于该人数**的对局才会生成这个点位。

- 仅信标、晶簇、物资箱（含黑市箱）有这个概念；
- 用法：标 8 人档才出现的点位填 `8`，6 人局就看不到它——用来做“大地图小地图”双形态；
- 出生点、控制点、出口等没有人数档（编辑器行里不显示人数框）。

### 6.4 点位 ID 命名

- 1–64 位小写字母、数字、`_`、`-`，如 `crystal_1`、`beacon_core`、`door_north`；
- **出生点例外**：用 0 起的连续下标（`0`、`1`、`2`……）；
- 同类型内不能重名；这个名字只写进配置用于区分点位，**和方块 ID 无关**。

### 6.5 编辑器操作（点位坐标页）

1. 左侧列表点击选择**点位类型**（每行显示 `id  中文名`）；
2. 填 **ID**（+需要时填**人数**）→ 点 **「标记」**（方块类对准方块，出生点类站在目标位置）；
3. 下方**自动列出该类型已设置的所有点位**：每行 `ID | 人数 | 坐标`：
   - 信标/晶簇/祭坛/物资箱/黑晶点/黑晶投放/核心门：行内直接改 ID 和人数（坐标不变，点 **「应用」** 即存入草稿），或点 **「删除」** 直接删；
   - 出生点：显示 `#下标 | 坐标 | [删除]`（下标不能改名，重新标记即改位置）；
   - 免费出口控制点/投机客出口：只能改 ID；
   - 单例类型（观战出生点/安全点/撤离相关）：只显示坐标，重新标记即覆盖，没有可删项；
4. 最底部是各字段的**数量统计**，方便对表。

### 6.6 命令操作

```text
/sre:echo map mark crystal crystal_1        # 准星对准晶簇方块
/sre:echo map mark beacon_core core_1 8     # 8 人档才出现
/sre:echo map mark carrier_spawn 0          # 走过去直接标（下标）
/sre:echo map remove beacons old_beacon     # 删除（field 见下表）
```

`remove` 的 10 个字段名：`carrierSpawns`、`interceptorSpawns`、`brokerSpawns`、`beacons`、`crystalNodes`、`altars`、`supplyCrates`、`blackCrystalNodes`、`blackDropoffs`、`doors`。

## 7. 第五步：框选区域体积（4 种）

| kind | 中文名 | id | 规则 |
|---|---|---|---|
| `core_area` | 核心区 | 不需要 | 整数半开框，≤100 万格，必须整个落在游戏区（playArea）内 |
| `core_door` | 核心门体 | **必须**（与 `core_control` 同 id） | ≤1024 格；先标同 id 的控制点再写体积 |
| `evacuation_door` | 撤离门体 | 不需要 | ≤1024 格 |
| `evacuation_zone` | 撤离检测区 | 不需要 | 与两个门体不得重叠 |

> 所有门体总体积 ≤1024 格、整数 AABB、互不重叠、不与撤离区重叠；
> 框是**半开盒**：你瞄的两个角方块都会算进去，“从这面墙瞄到那面墙”即可。

### 7.1 编辑器操作（区域体积页）

1. 列表选择**区域类型**；
2. 填门体 ID（仅 `core_door` 需要）→ 点 **「写入体积」**；
3. **角点 A / 角点 B** 输入框（同页）：
   - **「取自准星」**：准星对着的方块自动存入并显示在框内；
   - **手动输入**：框内直接敲 `x y z`（整数方块坐标）→ 点 **「应用输入」**；
   - 两个角设好后即可写入体积。

### 7.2 命令操作

```text
/sre:echo map corner a                # 准星瞄核心区一角
/sre:echo map corner b                # 瞄对角
/sre:echo map volume core_area        # 写入核心区
/sre:echo map mark core_control door_n
/sre:echo map corner a                # 重新瞄门体一角
/sre:echo map corner b
/sre:echo map volume core_door door_n # 写入门体
/sre:echo map volume evacuation_zone
```

## 8. 第六步：检查与保存

### 8.1 三种检查

| 检查 | 作用 | 说明 |
|---|---|---|
| **结构校验**（保存时自动执行） | 6 人至出生点容量上限逐档跑 `EchoMapValidator`（最多 32） | 数量、区域归属、间距、出生点重叠、门体几何；任一受支持档不过即拒存 |
| **世界校验**（已加载 Areas 地图时执行） | 目标点必须是非空气方块、门体每格实心无 BE、出生点安全、核心区在游戏区内、地图设置合规 | 没加载地图时跳过，留到开局预检 |
| **路线扫描** `map routes` | 步行图连通性：全门关闭时不能走进核心区；每扇门虚拟开启后核心内目标可达；撤离阶段撤离区可达 | 全服同时最多 2 个任务；结果分 **通过 / 失败 / 需人工** |

> 重操作（校验/预览/保存/路线）同一玩家两次执行至少间隔 1 秒。

### 8.2 保存

```text
/sre:echo map save echo_depot                  # 保存（自动校验）
/sre:echo map save echo_depot confirm <令牌>   # 覆盖已存在文件时的二次确认
```

- 保存前自动跑 6 人至出生点容量上限的全档校验，不过则拒存并列出问题；开局仍按实际人数严格校验，缺出生点直接拒绝，不循环复用出生点；
- **覆盖已存在的文件**会先发一次性令牌（30 秒有效），消息里的令牌可点击，或手动补 `confirm <令牌>`；
- 写入是**原子替换**；保存只影响下一局，不改当前对局。

编辑器里对应「保存检查」页：**「预览配置」**（客户端 30 秒框选预览）、**「保存地图配置」**、**「确认覆盖」**，下方是问题列表。

### 8.3 路线“需人工”怎么办

```text
/sre:echo map routes confirm <nonce>   # 人工放行本次结果
/sre:echo map routes cancel            # 取消进行中的扫描
```

正式开局时若路线准入为“需人工”，同样用一次性令牌确认（仅确认本次，不代表玩法验收）。

## 9. 第七步：启用为回声地图并开局

### 9.1 启用（gate）

```text
/sre:echo map gate on     # 把 echo_freight 写进当前 Areas 地图的 gameModes
/sre:echo map gate off    # 取消
/sre:echo map gate        # 只看当前状态
```

- 就是**把当前这张 Areas 地图标记为“可载入回声地图配置”**，与开局动作无关，改完立即写回地图配置；
- 编辑器里是「地图配置」页的 **「将此图启用为回声地图」** 按钮（需要已加载 Areas 地图）。

### 9.2 生效方式（二选一）

1. **同名自动匹配**：侧文件名 = Areas 地图名（`echo_station.json` ↔ 地图 `echo_station`），无需额外操作；
2. **switchmap 绑定**：任意名字的侧文件都能绑定生效——

```text
/sre:echo switchmap load echo_map      # 校验通过后绑定并生效
/sre:echo switchmap random             # 随机加载一个校验通过的
/sre:echo switchmap clear              # 清除绑定，回到按地图名自动匹配
/sre:echo switchmap                    # 查看当前状态 / list 列出全部
```

> 绑定优先级高于地图名；与 Areas 地图不同名时会提示“模板坐标需按当前图平移，请确认两图模板区一致”。

### 9.3 开局

```text
/tmm:start noellesroles:echo_freight
```

- **不带时长参数**（回声时长固定，命令会拒绝 `minutes >= 0`）；
- 需要 `-Dsre.echo.development=true` 启动、6–32 人在准备区，人数不能超过该图各阵营出生点容量；
- 预检依次检查：开发开关 → 人数 → 地图已加载 → 已启用为回声地图 → 地图设置合规 → 侧文件存在且 `mapId`/模板坐标匹配 → 结构+世界校验 → 路线准入 → 门状态恢复；
- 全部通过后按人数档分配身份、契约、专长并传送到各自出生点。

## 10. 方块选择建议

代码**不校验方块 ID**，只看“是不是空气”。以下纯主题搭配：

| 点位 | 推荐方块 | 理由 |
|---|---|---|
| 晶簇点 | 紫水晶块 | 采集音效即紫水晶 chime/break |
| 信标 | 铁块 | 提交/污染有自定义音效，铁块有“重器”感 |
| 祭坛 | 錾制石砖、磨制闪长岩 | 石质主题 |
| 普通物资箱 / 黑市箱 | 箱子 / 陷阱箱 | 主题贴切；局内右键触发搜索计时，不会真开 GUI |
| 控制点/出口 | 不显眼的整方块 + 灯笼/告示牌做标识 | 局内右键被模式拦截 |
| **门体（核心门+撤离门内每格）** | **铁块** | 开关门自带铁门音效；局内冒险模式拆不动 |
| 出生点脚下 | 任意完整实心方块 | 脚+头顶两格必须空出 |

全部是原版方块，在创造模式「建筑方块」「红石」页直接拿；模组装饰方块（暗金块、金属板等）也可用于目标点，但只有**完整立方体**能填门体。

## 11. 地图配置文件说明

### 11.1 位置

```
<世界根目录>/echo_freight/maps/<mapId>.json      # 地图侧文件（模板坐标）
<世界根目录>/echo_freight/rules.json             # 规则配置（门/信标/物流数值，与地图分开）
<世界根目录>/echo_freight/active.json            # switchmap 绑定
```

### 11.2 结构（`EchoMapConfig`，schemaVersion=1）

```json5
{
  "schemaVersion": 1,
  "mapId": "echo_depot",
  "coordinateSpace": "template",            // 必须是 template
  "coreArea":  { "minX":0,"minY":64,"minZ":0,"maxX":20,"maxY":70,"maxZ":20 },
  "carrierSpawns":    [ { "x":0.5,"y":64.0,"z":0.5,"yaw":0,"pitch":0 } ],   // 下标即 id

    "doors": [ { "id":"door_n","controlPos":{"x":10.5,"y":65.0,"z":10.5},
                 "volume":{"minX":8,"minY":64,"minZ":8,"maxX":12,"maxY":68,"maxZ":12} } ],

                  "controlPos":{"x":10.5,"y":65.0,"z":10.5},

  },
  "evacuation": {
    "controlPos":   { "x":4.5,"y":64.0,"z":4.5 },

```

字段要点：

- 所有坐标是**模板坐标**（保存时已按偏移换算），`coordinateSpace` 必须是 `template`；

当前 Areas 地图**不能**配置：`initialItems`、紧急会议、摇铃会议、小游戏任务、飞机坠落、场景任务、强制/启用角色或修饰器——否则开局被拒（`echo.error.map_settings`）。

## 14. 常见报错对照表

| 报错 | 原因 | 处理 |
|---|---|---|
| 请先用现有Areas工具加载实战地图 | 留空新建时既无绑定也无 Areas 地图 | 填地图 ID，或先 `/tmm:switchmap load <地图>` |
| 当前未加载Areas地图：请在地图ID框里填写地图ID… | 同上 | 同上 |
| 编辑mapId必须与当前Areas地图一致 | 旧版限制（已放宽） | 升级后忽略；现在可编辑任意侧文件 |
| 侧文件必须对应当前Areas地图 | 文件名/内部 mapId 与生效地图不一致 | 改名保存，或 `switchmap load <mapId>` 绑定 |
| 地图未启用回声托运站配置 | `gameModes` 没声明 `echo_freight` | `/sre:echo map gate on` |
| 回声托运站目前只能在开发模式下开局 | 缺 JVM 参数 | 加 `-Dsre.echo.development=true` |
| beacons 与人数档不符 | 生效信标数不对（≤7 人 2 座 / 8+ 人 3 座） | 用人数档筛选后核对 |
| 必需核心信标应为一座 | `beacon_core` 标了 0 或 ≥2 座 | 全图只留 1 座核心信标 |
| beacons.xxx 区域不匹配 | 核心信标没框进核心区，或开放信标误框进去 | 调整 `core_area` 或信标位置 |
| 开放晶簇数量不足 | 生效晶簇 <4（≤7 人）/ <6（8+ 人） | 补标，或下调已有晶簇的人数档 |
| 开放物资箱数量不足 | 生效普通箱 <6/8/10 | 同上 |
| 核心黑市箱数量不足 / 黑市箱必须在核心… | 黑市箱 <2 或不在核心区 | 补标并框进核心区 |
| altars 必须恰好三个 / altars 点间距不足 | 数量不是 3 或两两 <20 格 | 补/移祭坛 |
| 核心区至少两个入口 | `core_control` <2 | 至少 2 扇门 |
| 对立出生点距离小于24 | 截流者出生点离托运/投机出生点 <24 | 拉开距离 |
| xxx 必须在开放区且不在门体/撤离区 | 点位落进核心区/门体/撤离区 | 移到开放区 |
| 免费出口控制点必须在核心内部 | `free_control` 在区外 | 移进核心区 |
| 门体总体积超过1024 / 门体互相重叠 / 与撤离区重叠 | 体积几何违规 | 重设角点 |
| 门体必须是实心整方块（世界校验） | 门体积里有非空气/带 BE/碰撞不完整/流体 | 换成铁块等完整实心方块 |
| 出生点不安全 | 脚下不实/头顶有碰撞/流体/危险方块 | 整理出生点 |
| coreArea outside playArea | 核心区超出游戏区 | 缩小框选 |
| 路线检查：无法走进核心区（失败） | 门全关时开放区与核心区意外连通 | 堵住绕门路径 |
| 路线检查：需人工 | 半砖/梯子等特殊碰撞需人工判断 | `map routes confirm <nonce>` |
| 目标文件已存在…令牌 | 覆盖保存需二次确认 | 30 秒内点「确认覆盖」或 `save <id> confirm <令牌>` |

## 15. 完整流程示例

```text
# 0) 启动带 -Dsre.echo.development=true，6–32 人进服

# 1) 建筑：搭好开放区 + 核心区（墙留 2 个门口用实心方块封死）+ 撤离区

# 2) 加载实战地图
/tmm:switchmap load echo_station

# 3) 新建配置（编辑器：手持编辑仪右键 → 地图配置页 → 新建地图配置）
/sre:echo map new echo_station

# 4) 标点（编辑器：点位坐标页选类型 → 填ID/人数 → 标记；已有点位行内改/删）
/sre:echo map mark carrier_spawn 0        # 支持32人连续标 0..20（旧12人图 0..7）
/sre:echo map mark interceptor_spawn 0    # 支持32人 0..5（旧图 0..1）
/sre:echo map mark broker_spawn 0         # 支持32人 0..4（旧图 0..1）
/sre:echo map mark crystal crystal_1      # 准星对准晶簇，按人数档多标几个
/sre:echo map mark beacon_core core_1     # 核心区内唯一
/sre:echo map mark beacon_open open_1     # 开放区
/sre:echo map mark altar altar_1          # 共 3 座
/sre:echo map mark supply supply_1        # 按人数档 ≥6/8/10
/sre:echo map mark black_market bm_1      # 核心区内 ≥2
/sre:echo map mark black_node bn_1        # ≥2
/sre:echo map mark black_dropoff bd_1     # ≥2
/sre:echo map mark broker_exit be_1
/sre:echo map mark core_control door_n    # ≥2 扇
/sre:echo map mark free_control fe_1      # 核心区内
/sre:echo map mark evacuation_control ec_1
/sre:echo map mark spectator spec_1
/sre:echo map mark free_safe fs_1
/sre:echo map mark evacuation_safe es_1
/sre:echo map mark drop_anchor da_1

# 5) 体积（编辑器：区域体积页 → 设角点A/B → 写入体积）
/sre:echo map corner a                    # 核心区一角
/sre:echo map corner b
/sre:echo map volume core_area
/sre:echo map corner a                    # 门体一角（每扇门各来一次）
/sre:echo map corner b
```
