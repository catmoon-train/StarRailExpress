## 2. 新增的公共能力（Java 扩展）

全部在 `io.wifi.starrailexpress.client.ponder` 包，扩展 id 仍是 `starrailexpress:role_tutorial`。

### 2.1 `starrailexpress:role_items` —— 职业初始物品

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `role` | string | 职业 id，**支持只写路径**（如 `jester`），先按完整 id 查、查不到再按路径查 |
| `origin` | `[x,y,z]` | 第一个物品的位置，默认 `[2,1.4,3]` |
| `spacing` | number | 物品之间的间距，默认 0.8 |
| `max` | int | 最多摆几个，默认 4 |
| `linkId` | string | 生成的实体 linkId 前缀 |

物品**直接读 `RoleInitialItems.getInitialItemsForRole(role)`**，与游戏内开局发放的一致。
这样不必在场景 JSON 里逐条手写物品 id，职业改了初始物品也不用改场景。

### 2.2 `starrailexpress:role_death` —— 死亡动画

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `linkId` | string | 要倒下的玩家模型（`role_player` 登记的 linkId） |
| `pos` | `[x,y,z]` | 尸体生成位置；省略时取模型当前位置 |
| `name` | string | 尸体名。含 `.` 且不含空格时按**翻译键**处理，否则按字面文本 |
| `entity` | string | 尸体实体 id，默认 `trainmurdermystery:player_body` |
| `delay` | int | 兼容旧场景保留，当前不生效 |
| `yaw` | number | 尸体朝向 |

流程：**模型立即消失 → 在同一坐标生成尸体实体**。不再摆趴下姿态：游戏里被击杀的
玩家就是直接移除、原地留下 `player_body`，思索按同一表现演出。

尸体名用 JSON 文本组件写入：`Entity.load` 是用 `Component.Serializer.fromJson`
解析 `CustomName` 的，直接写 `'酒保'` 会在加载时抛 `JsonSyntaxException`，
整个场景会被判为 unavailable。翻译键写法（`{"translate":"..."}`）还能让名字随客户端语言显示。

### 2.3 `starrailexpress:role_screen` —— 技能界面（背包选人列表）

神权冷笑、巫毒师、变形者等 19 个职业的技能是**在背包界面里挑一个玩家**来施放
（`RoleScreenHelper` 挂在背包上的一排玩家头像）。离屏沙盒构造不出真实背包，
因此按同一版式自绘一份：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `title` | string / 三语对象 | 面板标题 |
| `hint` | string / 三语对象 | 面板下方提示 |
| `players` | string[] | 列表里的玩家名，默认 `Steve / Alex / Notch / Dinnerbone / jeb_ / Herobrine` |
| `columns` | int | 每行个数，默认 6 |
| `color` | int | 标题颜色 |

头像用默认玩家皮肤填充（`minecraft:textures/entity/player/wide/steve.png` 与 `alex.png`），
思索是离屏场景、没有真实在线玩家，用固定用户名与默认皮肤才能保证每次播放画面一致。

### 2.4 `starrailexpress:role_ambience` —— 环境染色

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `color` | int | RGB |
| `alpha` | number | 0~1，默认 0.45 |
| `mode` | string | `sky`（天顶渐变）/ `fog`（整体染色），默认 `fog` |

Ponder 离屏沙盒没有服务端的天空、雾与全局光照入口，只能用屏幕染色近似。
颜色优先级按 `docs/halloween-ambience.md`：命令方块紫 > 万圣节橙，黑暗 / 失明的黑雾再压过橙色。

### 2.5 覆盖层支持三语

`role_skill` / `role_panel` / `role_bond` / `role_render` / `role_disguise` / `role_mood` /
`role_vitals` / `role_timer` / `role_effects` / `role_currency` 的 `lines` 与 `title`
现在接受 `{en_us, zh_cn, zh_tw}` 对象（也仍然接受单语言字符串）。
解析方式与场景 `text` 步骤一致：当前语言 → `en_us` → 首个可用值。

实现见新增的 `PonderLocalizedText`。

## 3. 新增的结构

| 结构 | 尺寸 | 用途 |
| --- | --- | --- |
| `role_tutorial_room` | 7×4×7 | 标准房间：木地板、房间木门、床、茶几、沙发、壁灯 |
| `role_tutorial_carriage` | 9×4×7 | 列车车厢：不锈钢地板、侧壁车窗、长条座椅、端门、灯条 |
| `role_tutorial_corridor` | 7×4×9 | 门与走廊：钢门、检票闸机、扶手、壁灯、监控 |
| `role_tutorial_graveyard` | 7×4×7 | 墓地：黑大理石地面、棺材、栏杆墓碑、提灯 |
| `role_tutorial_water` | 7×4×7 | 水域：玻璃围出的池子、钢制走道、水阀与水泵 |
| `event_command_room` | 7×4×7 | 命令方块事件舞台：黑船体板机房、监控、反应堆、灯条 |
| `event_night_town` | 9×4×7 | 黑夜事件舞台：夜间小镇广场、路灯、信箱、长桌 |
| `event_halloween_porch` | 7×4×7 | 万圣节事件舞台：门廊、木地板、提灯、柜子 |

本模组没有水方块（水是原版），因此水域结构用玻璃围出池子 + 钢走道 +
本模组的 `noellesroles:water_valve` / `water_pump` 任务点方块点明语义。
结构调色板里不允许出现 `minecraft:` 方块（`tools/verify_ponder_structures.py` 会拦）。

## 4. 生成流水线

```bat
python tools/extract_ponder_role_facts.py   :: 职业事实 -> tools/ponder_role_facts.json
python tools/generate_ponder_structures.py   :: 生成结构 NBT
python tools/verify_ponder_structures.py     :: 校验结构 NBT
python tools/gen_ponder_scenes.py            :: 生成 269 个场景 + 场景索引
python tools/verify_ponder_scenes.py         :: 场景自检（结构 / 三语 / 时间轴 / 原文引用）
python tools/fix_ponder_scene_timeline.py    :: 补足段落末尾 idle
python tools/fix_ponder_custom_name.py       :: CustomName 改成 JSON 文本组件
```

### 4.1 事实提取（`extract_ponder_role_facts.py`）

扫描源码得到：职业 id → 常量名、注册文件、颜色、是否平民 / 杀手阵营、
是否其它模式职业、是否事件载体、是否警长阵营、疯狂模式皮肤贴图、
初始物品、商店条目、是否声明了背包界面扩展。

### 4.2 场景生成（`gen_ponder_scenes.py`）

段落划分：把介绍原文的每一句按关键词打分归到某个段落
（物品 / 技能 / 界面 / 商店 / 尸体 / 面板 / 透视 / 心情 / 数值 / 绑定 / 形态 / 领域 / 其它），
命中关键词多的段落优先，同数时按上表顺序。

每段的固定骨架：

```text
show_structure
role_player（职业本人）
<该段专属的演示步骤>
text（逐句引用介绍原文）
idle（≥ 上一条 text 的 duration）
rotate_camera_y
```

各段的演示步骤：

| 段落 | 演示 |
| --- | --- |
| `faction` | 职业本人 + 阵营首行 + 阵营关系行 + 胜利目标 |
| `items` | `role_items`（真实初始物品）；没有初始物品但有商店时摆一件商店商品 |
| `skill` | `role_key`（按下技能键）+ `role_skill` 面板 |
| `screen` | `role_screen`（背包选人列表） |
| `shop` | `role_shop`（真实商店数据） |
| `body` | 第二名「受害者」模型 + `role_death`（倒下 → 消失 → 同位置生成尸体） |
| `panel` | `role_panel`（文书 / 界面） |
| `vision` | 第二名玩家带本能透视边框 + `role_render` |
| `mood` | `role_mood`（心情值变化条） |
| `vitals` | `role_vitals`（虚拟血量 / 护盾条） |
| `bond` | 第二名玩家 + `role_bond` |
| `form` | 第二名玩家（疯狂皮肤，若有）+ `role_disguise` |
| `domain` | `role_domain`（六个领域场景之一） |

胜利目标取 `announcement.star.goals.<id>`；该键不存在时按阵营关系用一句通用目标
（击杀所有杀手 / 协助平民 / 击杀所有平民 / 协助杀手 / 协助好人）。

## 5. 自检结果

`tools/verify_ponder_scenes.py` 覆盖 272 个场景：

- JSON 可解析，必需字段齐全，`items` 非空；
- 段落 id 唯一，首步是 `show_structure`；
- 时间轴：相邻两条 `text` 的占位区间不重叠，段落最后一条 `text` 之后也有足够 `idle`；
- 同段 `text` 的 `point` 互不相同；
- 自定义步骤的参数都写在 `parameters` 里；
- 引用的结构 NBT 存在；
- 场景索引登记了全部场景，且指向的文件存在；
- 正文逐句取自介绍原文（允许阵营首行、阵营关系行、职业目标与通用胜利目标）。

当前结果：**0 error**。

另有 2 条 warning，来自酒保 / 小丑两个既有场景里手写的总结句
（「护盾显示蓝色，护盾加毒显示黄绿色，只有毒显示红色」等），是有意保留的说明性文字。

### 5.1 本次一并修掉的既有问题

1. **场景索引的路径格式错了**。Ponderer Lib 的清单格式是 `<命名空间>:<路径>`
   （见 Ponderer `docs/PONDERER_LIB.md`），原来写成 `starrailexpress/ponderer/scenes/xxx.json`，
   `ResourceLocation.parse` 解析不出 `namespace:path`，三个老场景实际上都没被加载。
   现已全部改成冒号格式。
2. **段落末尾 idle 不足**。酒保、小丑两个场景每段最后一条文本之后只留了 30~50 tick，
   文案还没读完镜头就转走了。已按「≥ duration」补足。
3. **CustomName 不是 JSON 文本组件**。`'酒保'` 会被 `Component.Serializer.fromJson` 拒绝，
   改成 `{"text":"酒保"}` / `{"translate":"..."}`。

## 6. 已知限制

- **介绍原文过长时只能引用主线**。规划第 9 节要求 2000 字以上的介绍只演示主线。
  本实现每个场景最多引用 12 句介绍原文，被省略的句子统计在 `tools/ponder_scene_report.json`
  的 `omitted` 里（共 20 个职业，最长的 `ma_chen_xu` 省略 15 句、`roulette_devil` 省略 9 句）。
- **领域只覆盖了已分配的六个**。`ModEffects.DOMAIN_MARK` 的 0~5 级分别对应
  愚者开会 / 灰髓之境 / 格罗赛尔游记 / 吞月 / 水中镜 / 秘密黑室，
  鬼眼·杨间、摘星者、律令法师的「领域」不是这套标记，因此只作文字展示。
- **环境层是近似的**。离屏沙盒没有天空 / 雾 / 全局光照入口，
  紫天、橙天、夜雾都用 `role_ambience` 的屏幕染色近似，视觉上不等于真实对局。
- **双条 HUD 只是近似**。命令方块事件的「破坏进度 + 事件倒计时」用 `role_vitals` 的两条数值条表示，
  样式与真实 HUD 不一致。
- **概率分支只能按段落叙述**。60/30/10、20% 这类随机结果不能呈现在线性时间轴上，
  事件场景按段落叙述并写明概率。
- **商店条目依赖运行时注册**。`role_shop` 读的是真实 `ShopEntry`，
  如果运行时商店表为空（`RoleShopHandler` 没注册成功）覆盖层就是空的。
- **实机播放尚未人工确认**。本次只做了静态自检与编译校验，
  还需要在客户端里逐场景播放一遍，确认 `run/logs/latest.log` 出现
  `loaded N scenes` 且没有 `scene ... unavailable`。
