# 如何创建 StarRailExpress 扩展模组

本文档面向希望为 StarRailExpress 编写独立扩展模组的开发者，涵盖从环境准备到项目构建的完整流程。  
关于代码层面的 API（注册角色、技能、事件等），请参阅 **[api.md](api.md)**。

---

## 重要提醒
CCA组件尽量少同步，否则会造成网络拥挤。

对于倒计时，建议客户端模拟计算，或者存储触发时间。实在需要手动倒计时，建议服务端仅在**10s同步一次**，客户端同步计算。

## 创建新项目

### 方式一：使用 Fabric 模板生成器（推荐）

访问 [Fabric 模板生成器](https://fabricmc.net/develop/template/) 填写以下信息后下载模板：

- **Minecraft Version：** `1.21.1`
- **Project Name / Mod ID：** 填写你的模组名称与 ID
- **Package Name：** 填写你的 Java 包名

下载解压后进入项目目录，继续配置构建文件（见下节）。

### 方式二：手动建立目录结构

```
你的模组/
├── src/
│   └── main/
│       ├── java/
│       │   └── com/example/yourmod/
│       │       └── YourMod.java
│       └── resources/
│           ├── fabric.mod.json
│           └── yourmod.mixins.json   # 如需 Mixin
├── gradle/
│   └── wrapper/
│       ├── gradle-wrapper.jar
│       └── gradle-wrapper.properties
├── build.gradle
├── gradle.properties
├── gradlew
├── gradlew.bat
└── settings.gradle
```

## 配置构建文件

### gradle.properties

```properties
# Gradle 选项
org.gradle.caching=true
org.gradle.parallel=true
org.gradle.jvmargs=-Xmx2G

# Minecraft / Fabric 版本（需与 StarRailExpress 保持一致）
minecraft_version=1.21.1
loader_version=0.19.3
fabric_api_version=0.116.13+1.21.1

# 你的模组属性
mod_version=1.0.0
maven_group=com.example
archives_base_name=your_mod_id
```

### build.gradle

```groovy
plugins {
    id 'fabric-loom' version '1.17.13'
    id 'maven-publish'
}

version = project.mod_version
group = project.maven_group

base {
    archivesName = project.archives_base_name
}

repositories {
    // Fabric
    maven { url "https://maven.fabricmc.net/" }
    // Cardinal Components（如需 CCA）
    maven {
        name = "Ladysnake Mods"
        url = 'https://maven.ladysnake.org/releases'
    }
    // Modrinth（Wathe 等前置）
    maven {
        name = "Modrinth"
        url = "https://api.modrinth.com/maven"
        content { includeGroup "maven.modrinth" }
    }
}

dependencies {
    minecraft "com.mojang:minecraft:${project.minecraft_version}"
    mappings loom.officialMojangMappings()
    modImplementation "net.fabricmc:fabric-loader:${project.loader_version}"
    modImplementation "net.fabricmc.fabric-api:fabric-api:${project.fabric_api_version}"

    // ——— StarRailExpress 依赖 ———
    // 先在本地构建 StarRailExpress（./gradlew build），
    // 构建产物是 build/libs/starrailexpress.jar（archives_base_name=starrailexpress，
    // 且 build.gradle 里 remapJar 设了 archiveVersion='' 所以**不带版本号**、也不产出 -sources）
    // 把它放进本项目的 libs/ 再引用：
    modImplementation files("libs/starrailexpress.jar")

    // ⚠️ 不要引入 Wathe 的真实模组（会因未初始化而崩溃）。
    // StarRailExpress 自己用的是 libs/wathe-1.3.2.jar（只保留部分接口的空壳），
    // 你的附加模组一般不需要引用它；需要时也用同一个空壳 jar，而不是 Modrinth 上的发布版：
    // modImplementation files("libs/wathe-1.3.2.jar")
}

processResources {
    inputs.property "version", project.version
    inputs.property "minecraft_version", project.minecraft_version
    inputs.property "loader_version", project.loader_version
    filteringCharset "UTF-8"

    filesMatching("fabric.mod.json") {
        expand "version": project.version,
               "minecraft_version": project.minecraft_version,
               "loader_version": project.loader_version
    }
}

def targetJavaVersion = 21
tasks.withType(JavaCompile).configureEach {
    it.options.encoding = "UTF-8"
    if (targetJavaVersion >= 10 || JavaVersion.current().isJava10Compatible()) {
        it.options.release.set(targetJavaVersion)
    }
}

java {
    def javaVersion = JavaVersion.toVersion(targetJavaVersion)
    if (JavaVersion.current() < javaVersion) {
        toolchain.languageVersion = JavaLanguageVersion.of(targetJavaVersion)
    }
    withSourcesJar()
}
```

> **如何获取 StarRailExpress JAR：**
> 1. 克隆 StarRailExpress 源码仓库
> 2. 在仓库根目录执行 `./gradlew build`（需要网络访问各 Maven 仓库；依赖已缓存时可加 `--offline`）
> 3. 构建产物位于 `build/libs/starrailexpress.jar`（**不带版本号**，也没有 `-sources` jar —— `build.gradle` 里 `remapJar { archiveVersion = '' }` 且 `withSourcesJar()` 被注释掉了）
> 4. 将该 JAR 复制到你的模组项目的 `libs/` 目录
>
> 若 `GRADLE_USER_HOME=E:\gradle_home` 报 `Plugin [id: 'fabric-loom'] was not found`，说明该目录缓存不全，改用默认 gradle home（`~/.gradle`）即可。

### settings.gradle

## 模组基本结构

### fabric.mod.json

```json
{
  "schemaVersion": 1,
  "id": "your_mod_id",
  "version": "${version}",
  "name": "Your Mod Name",
  "description": "你的模组描述",
  "authors": ["你的名字"],
  "license": "GPL-3.0-only",
  "environment": "*",
  "entrypoints": {
    "main": ["com.example.yourmod.YourMod"],
    "client": ["com.example.yourmod.client.YourModClient"]
  },
  "mixins": [
    "yourmod.mixins.json"
  ],
  "depends": {
    "minecraft": "1.21.1",
    "fabricloader": ">=0.19.3",
    "fabric-api": "*",
    "starrailexpress": "*",
    "wathe": "*",
    "cloth-config": "*",
    "modmenu": "*",
    "voicechat": "*",
    "architectury": "*",
    "exposure": "*",
    "sre_resource": "*"
  }
}
```

> 依赖 id 注意：**Fabric Loader 的 mod id 是 `fabricloader`（不是 `fabric-loader`）**，写成 `fabric-loader` 会导致加载期依赖解析失败。
> 上面列出的 `cloth-config` / `modmenu` / `voicechat` / `architectury` / `exposure` / `sre_resource` 是 StarRailExpress 自身 `fabric.mod.json` 里的硬依赖（`depends`），运行时缺一个都起不来，所以你的附加模组里也应当声明它们（或在开发环境里确保它们在场）。
> `license` 按你自己的选择填；顺带一提：StarRailExpress 本体是 **GPL-3.0-only**（见 `LICENSE.txt` 与 README），`src/main/resources/fabric.mod.json` 里写的 `LGPL-3.0` 与仓库实际许可证不一致（属元数据笔误），引用本模组时请以 `LICENSE.txt` 为准。

### 主类示例

```java
package com.example.yourmod;

import net.fabricmc.api.ModInitializer;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

public class YourMod implements ModInitializer {

    public static final String MOD_ID = "your_mod_id";
    public static final Logger LOGGER = LoggerFactory.getLogger(MOD_ID);

    @Override
    public void onInitialize() {
        LOGGER.info("YourMod 初始化完成");
        // 在此注册角色、物品、事件监听器等
        // 详见 api.md
    }
}
```

## 项目构建命令

以下命令均在项目根目录下执行（Windows 使用 `gradlew.bat`，Linux/macOS 使用 `./gradlew`）：

| 命令 | 说明 |
|------|------|
| `./gradlew build` | 编译并打包模组，产物输出至 `build/libs/` |
| `./gradlew runClient` | 启动测试用 Minecraft 客户端（含你的模组） |
| `./gradlew runServer` | 启动测试用 Minecraft 服务端 |
| `./gradlew genSources` | 生成 Minecraft 反混淆源码（IDE 调试用） |
| `./gradlew clean` | 清理构建缓存 |
| `./gradlew --refresh-dependencies build` | 强制重新下载依赖后构建 |

> **构建产物说明：**
> - `build/libs/your_mod_id-<version>.jar` — 正式发布 JAR
> - `build/libs/your_mod_id-<version>-sources.jar` — 源码 JAR（可选）

## 注册扩展内容

项目搭建完成后，请参阅以下文档了解如何在代码中注册各类扩展内容：

- **[api.md](api.md)** — API 参考（角色、修饰符、技能、事件、HUD、CCA 组件等）。**注意该文件部分符号已过时，代码以源码为准**
- **[../CreateExtention.md](../CreateExtention.md)** — 快速参考：角色、物品、实体、商店、网络包、GUI 与 Mixin。⚠️ 该文档是给「**在本仓库里**加内容」用的（直接改 `ModRoles.java` / `Noellesroles.java` / 本仓库的 mixins.json）；写**独立扩展模组**时只能调用公开 API，不能按它改本仓库文件
- **[角色开发指南.md](角色开发指南.md)** 与 **[AI创建新职业攻略.md](AI创建新职业攻略.md)** — 新增职业的完整流程、模板与踩坑清单

> **重要提醒：**
> - **不要引用 Wathe 的发布版**，它会导致崩溃（未初始化状态）。本仓库自己用的是 `libs/wathe-1.3.2.jar`（只保留部分接口的空壳），需要时照做。
> - 添加 Mixin 后需在 `yourmod.mixins.json` 和 `fabric.mod.json` 中同步注册。
> - 网络包遵循命名惯例：C2S 包放在 `packet/` 下，继承 `CustomPacketPayload`；注册在 `ModPackets#registerPackets()`（服务端接收写在 `ModPacketsReciever#registerPackets()`，且**接收器只做薄转发**，逻辑放进职业类/Handler）。
