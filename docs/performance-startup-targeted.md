# 针对性启动优化：服务端语言下载客户端按需初始化

## 定位与改动

此前实际整包入口计时中，SRE 初始化约 6.72 秒，但包含类加载、Mixin 和调用依赖成本，不能全部视为可消除时间。ModernFix 的约 10.59 秒主要记在首次入口类加载边界，反编译未发现对应的重型构造逻辑，因此未据此删除或改动 ModernFix。

本轮确认一个具体的客户端无效工作：`SRE.onInitialize()` 调用 `ServerLanguageManager.applyFromConfig()`；后者虽然立即排除客户端环境，但旧静态字段已经先构建了 Java `HttpClient`，触发 HTTP/TLS 初始化。该客户端实际只用于专用服务器后台下载原版语言文件。

将 HTTP 客户端移到静态内部类 `HttpClientHolder`，只在 `httpGet()` 真正发送请求时初始化。JVM 类初始化保证并发首次访问安全，后续下载仍复用一个客户端。保留原有 10 秒连接超时、NORMAL 重定向、20 秒请求超时、User-Agent、流量记录、缓存和语言安装行为；未新增依赖、线程或配置开关。

这属于核心服务端语言功能自身的初始化修正，不是新增整合包第三方兼容补丁，因此留在核心模块。

## 验证

执行 `./gradlew :test :remapJar --offline --console=plain`：构建成功，核心 **691 项测试通过，0 失败、0 跳过**。

新增两个回归测试：

- 隔离类加载器禁止加载下载客户端 Holder 时，语言管理器仍能完成初始化。
- 16 个并发访问取得相同 HTTP 客户端，连接超时与重定向配置保持不变；不发送网络请求，测试结束关闭客户端。

发布 JAR 已确认包含 `ServerLanguageManager$HttpClientHolder.class`。本轮没有改动独立兼容模块，未重复运行其此前通过的测试。

## 实机边界

用户在准备采样后选择“先只做源码优化与构建”，因此没有启动游戏、没有产生新的 JFR 或启动 A/B 数据，也没有覆盖实例已安装的核心或兼容 JAR。**未量化整包启动提速，不将此前单次 113.7 秒当作本轮基线。** HTTP 初始化可能已被其他组件提前触发，最终墙钟收益仍需同实例交替对照确认。

临时诊断参数已通过启动器原生控件清除；`PCL/config.v1.yml` 已核对实例额外 JVM 参数为空（继承原全局参数），不含计时代理或 JFR 参数。实例核心和兼容 JAR 的 SHA-256 均保持原值，未部署新产物。
