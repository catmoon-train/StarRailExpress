# 11 · 手工验收清单（真人 / 真实客户端）

> 本文件只覆盖**自动化无法证明**的部分：真实方块地图、多客户端、GUI、语音与性能。纯单元测试与构建成功已在 [实现进度](IMPLEMENTATION-PROGRESS.md) 记录，不在此重复。每项写明操作、预期与失败判定；失败即记缺陷，不得以“测试通过”替代。

## 0. 前置条件

| 项 | 要求 |
|---|---|
| 开发开关 | 服务端启动参数含 `-Dsre.echo.development=true`；未设置时必须被拒绝（已在隔离服务端实测） |
| 运行目录 | 使用独立实例或备份后的开发世界，不要直接在正式存档上首次开局 |
| 地图 | Areas 中已存在 `gameModes` 含 `echo_freight` 的地图，且 `<world>/echo_freight/maps/<mapId>.json` 通过 `map validate` |
| 人数 | 6–12 名真实客户端；本清单以 6 人为最小档 |
| 权限 | 至少一名 OP2 执行命令；其余玩家无 OP |
| 记录 | 开启服务端日志，保留 `latest.log` 与 `echo_freight/results` 产物 |

## 1. 地图制作与保存

1. OP2 用现有 Areas 工具加载目标实战图，确认处于 INACTIVE。
2. `sre:echo map new <mapId>` → 预期 `echo.map.editing`；未加载 Areas 地图时应提示“请先用现有Areas工具加载实战地图”。
3. 依次 `map mark` 全部必需点位：三种出生、观战、信标、晶簇、祭坛、黑晶节点/投放、黑市、`broker_exit`、`core_control`、`free_control/free_safe`、`evacuation_control/evacuation_safe`、`drop_anchor`。
4. `map corner a` / `map corner b` + `map volume` 设置 `core_area`、各 `core_door`、`evacuation_door`、`evacuation_zone`。
5. `map validate` → 预期列出所有剩余问题；补齐后为空。
6. `map save <mapId>` → 首次直接保存；再次保存同一文件应要求 `confirm <nonce>`，且 30 秒后过期、重放无效。
7. `map preview` → 仅操作者看到框与标签，30 秒消失；其他玩家无提示。

**失败判定**：任何点位写错坐标、保存后文件 SHA 未变、覆盖确认可重放、预览发给非操作者。

## 2. 开局与路线准入

1. 6 人进入就绪区，OP 执行 `tmm:start noellesroles:echo_freight`。
2. 预期：地图重置 → 分帧路线扫描 → 成功才分配身份；失败时统一回到 INACTIVE，且日志出现 `回声开局预检未通过` 或 `回声开局路线准入未通过`。
3. 带分钟参数 `tmm:start noellesroles:echo_freight 10` → 必须被 `echo.error.fixed_duration` 拒绝。
4. 故意在扫描期间用活塞/命令改动门体方块 → 应撤销许可或转 MANUAL，不得放行。
5. 若被降级为 MANUAL，OP2 执行 `sre:echo map routes confirm <nonce>` → 仅在 STARTING、30 秒内、原地形下有效；`routes cancel` 可中止。

**失败判定**：半局（已分配身份但未开始）、失败后仍可操作、令牌可重复使用、改地形后仍放行。

## 3. 物流与信标

1. 托运者空手长按右键采集晶体 → 4 秒进度，完成后货槽 +1，附近有采集声/粒子。
2. 提交到信标 → 1 秒，公共 HUD 已交数 +1；三枚后自动充能，进度条与光柱出现。
3. 截流者迟滞 → 20 秒引导，成功后充能停 20 秒；进度不倒退，已启动信标免疫。
4. 撤离阶段：核心门保持开放，撤离区停留 2 秒离场，Q 计数正确。
5. 过载：截流者 G 在撤离控制器 12 格内，共享一次，关闭撤离门 30 秒，主计时继续。

**失败判定**：进度与公共数字不一致、冷却可绕过、已撤离者被重复计数、过载关闭主计时。

## 4. 战斗与两次机会

1. 截流器蓄力 0.6 秒后命中 → 目标 DOWNED，900 tick 流血；再命中不补刀。
2. 空手救援 2.5 格、5 秒 → WOUNDED + 120 tick 保护；保护期内再次命中应被忽略。
3. 倒地者：视角保留、移动被禁、不可使用物品；流血耗尽自动淘汰。
4. 托运者 G 推挡 2.5 格 → 25 tick 控制，成功才进入 500 tick 冷却。
5. 环境致命（坠落/岩浆）→ 送回出生点、60 tick 控制、200 tick 复位保护。

**失败判定**：首次命中直接死亡、普通武器绕过机会数、保护期无效、倒地可移动。

## 5. 六格背包与开包

1. 背包入口可见且保留 parent；六格编号固定。
2. 开包 1.5 秒引导，取消后 10 秒冷却；三候选同屏显示图标/名称/实际参数。
3. 选卡后入原保留格；任一候选含 KEY 时显示配额提示。
4. 拖拽失败必须恢复服务器最新布局，不留旧拖影。
5. 满包丢弃/拾取、同品质包同格两实例、卡/KEY 一格一份。

**失败判定**：候选在 OFFERED 前可见、本地先扣物、版本冲突后自动重发写请求、KEY 超上限。

## 6. 卡牌效果（逐卡）

按 [05 卡牌目录](05-card-catalog.md) 的 37 张卡，每张至少验证：成功一次、失败不扣、目标失效、叠加拒绝、掉线清理、结算清理、接收方正确。

重点复验本轮新接入项：

| 卡 | 操作 | 预期 |
|---|---|---|
| `short_dash` / `long_dash` | 修改 `cards.short_dash.durationSeconds` 后开局 | 详情显示新秒数，加速持续同步变化 |
| `silent_dummy` | 改 `deceptionRange` 后放置 | 狼嗅探仅在新区间内被诱导 |
| `false_dispatch` | 两点相距小于 `minSeparation` | 拒绝且不扣卡 |
| `salvage_magnet` | 改 `pickupRange` | 吸包距离与说明一致 |
| `pack_hook` | 对满包自己使用 | 拒绝，目标包不转移 |
| `master_key` | 门内无狼时使用 | 开门成功仍消耗 KEY |

**失败判定**：说明显示默认数字而非配置值、效果与参数不一致、失败扣卡。

## 7. 交易与契约

1. 投机客 G 对准 3 格内玩家 → 提案；超出范围/无视线拒绝且不进冷却。
2. 报价后对方修改 → 本人确认态立即取消。
3. 双确认后成交一次；16 格内可听到成交声。
4. 赠送（单方为空）允许；双方为空拒绝。
5. 四种契约各自达成：走私两处黑晶、情报双向真实交易、拾荒三次开包后存活到正常结束、钥匙贩子真实消费 KEY。
6. 契约成功后到 `broker_exit` 停留 3 秒退场；移动会重置停留。

**失败判定**：未双确认即成交、确认后改价仍成交、契约可用假信号推进、退场后可再行动。

## 8. 断线、重连与旁观

1. 断线 → 600 tick 宽限；期间资源在最后安全点掉落，动作/交易取消。
2. 宽限内重连 → 同一背包/货槽/契约/生命状态，新请求序号，不补初始包。
3. 第二次断线或宽限过期 → 永久退出，资源只掉一次。
4. 陌生 UUID 加入 → 只能旁观，HUD 不显示他人手牌/契约。
5. 暂停时断线 → 宽限冻结；恢复后按原截止继续。

**失败判定**：重连刷新保护/奖励、资源重复掉落、旁观者看到私有数据。

## 9. 客户端与 UI

1. GUI 缩放 1/2/3/4、逻辑分辨率 320×240 / 640×360 / 960×540：三选一、确认按钮、交易面板始终可达。
2. 三语（简中/繁中/英文）长文案不溢出、不遮挡按钮。
3. ESC 优先取消两点预选/拖拽，再返回父屏。
4. HUD：公开区（阶段/信标/撤离/门/过载）与本人区（货物/生命/KEY 脉冲/技能/装备）不重叠，普通模式身份/金币/心情 HUD 在 Echo 中隐藏。
5. 引导进度条封顶 99.9%，服务端完成才结束；拒绝提示限时消失。
6. 假影：宽臂与细臂皮肤分别正确；不阻挡射线、不可救援。
7. 工具：截流器与卡牌代理显示各自贴图，不显示铁剑/地图占位。

**失败判定**：按钮被遮挡、文字截断、HUD 相互覆盖、假影用错模型、工具贴图错。

## 10. 音频与信号

1. 提交声：任意距离可闻，方向来自信标而非听者位置；大地图远端仍可分辨左右。
2. 静默采集：成功采集/提交无声光，但持续货物回声与公共进度保留。
3. 假提交与真提交声音一致；公共 HUD 数字不变。
4. 信标充能：32 格内可见光柱，16 格内低鸣；封锁/暂停时低鸣停止。
5. 交易成交声 16 格内可闻；门机械声 32 格内可闻。
6. 双面面具抑制一次普通 KEY 脉冲，但不抑制契约脉冲。

**失败判定**：声音来自听者位置、静默压制公共数字、假提交推进目标、暂停仍有低鸣。

## 11. 性能与稳定性

1. 6 人与 12 人各跑一局完整流程，记录 TPS 与内存。
2. 开局路线扫描期间观察是否明显卡顿；`Done` 后无持续 2 秒以上停顿。
3. 连续 20 次开关背包不累积控件、不重复注册监听。
4. 连续 10 次重连不泄漏会话；结束后 `echo_freight/results` 有产物、无残留门体日志。
5. 服务端重启：未完成门体日志按预期恢复或告警，不覆盖外部编辑。

**失败判定**：TPS 持续低于 15、内存持续增长、结果文件缺失、门体未恢复。

## 12. 记录模板

每条失败记录：场景、操作、预期、实际、`latest.log` 片段、是否可复现、是否涉及资源/结果一致性。修复后必须重跑该项与本文件对应章节，不得只跑单元测试。

## 13. 阵营专长与开局揭晓

规则见 [12 专长与开局揭晓](12-specializations.md)。

1. 6 人开局后 3 秒内出现阵营揭晓卡（阵营色、契约名仅投机客、进度线）；按任意移动键可跳过。
2. 揭晓结束自动打开专长界面；两张卡片显示名称与效果，底部有确认/默认/返回。
3. 超时不选 → 默认专长；再次打开界面显示“已锁定”。
4. 选择 `porter` 后货槽 +1、搬货减速下降；选择 `scout` 后采集更快、货槽 -1。
5. 选择 `hunter` 后截流器蓄力与冷却缩短；`saboteur` 迟滞引导更快但冷却变长。
6. 选择 `smuggler` 后黑晶采集更快；`fixer` 交易范围 +2、提案冷却缩短。
7. 断线重连：已选专长保留；未选且窗口开放时界面重新弹出。
8. 进入 OPERATIONS 后 `/sre:echo_spec` 应提示“已结束”，界面只读。
9. 旁观者看不到揭晓卡与界面；伪装不改变候选集合。
10. 结果产物包含每名玩家的专长 ID。

**失败判定**：揭晓卡阻塞移动或接管相机、超时未落默认、OPERATIONS 后仍可改、跨阵营候选、说明数值与实际不符。

## 14. 动画与演出检查

1. 打开背包/交易/契约/专长界面：背景与面板约 0.2 秒淡入，并有一次点击音效；快速缩放窗口不重复播放入场。
2. 开包候选：三张卡依次出现（约 90ms 间隔），不是同时闪现。
3. 专长界面：鼠标悬停卡片有金色描边；最后 5 秒倒计时转红并闪烁。
4. 交易面板：最后 10 秒倒计时转红；改价后确认态立即取消。
5. HUD：拾取晶体/钥匙时货物行短暂变金色；倒地/救起时生命行短暂提亮。
6. 假影：消失前约 1 秒逐渐变淡，不会瞬间消失。
7. 信标充能：光柱有轻微呼吸，暂停时停止呼吸。
8. 揭晓卡：淡入淡出，不遮挡移动与准星。
9. 物品：截流器与卡牌终端在物品提示中显示名称与描述，长描述包含操作步骤与“失败不扣卡”。

**失败判定**：动画阻塞点击、淡入期间按钮错位、倒计时颜色与实际剩余不符、假影瞬间消失、描述缺失或与实际行为矛盾。
