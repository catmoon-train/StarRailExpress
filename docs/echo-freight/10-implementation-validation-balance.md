# 10 · 实现阶段、验证矩阵与平衡试验

> 本文是后续开发工作与完成判断的权威清单，**不是已执行测试报告**。本次交付仅Markdown；下面Java测试、多人测试、性能目标尚未执行。

## 1. 实现依赖与交付阶段

代码主目录按 [06](06-server-architecture.md)；每阶段完成一个功能块后集中测试，避免同一阶段零散反复构建。阶段1–3是最小可玩闭环，不能代替完整首发；阶段4–7包含全部卡池、中立与安全交易。

```text
阶段0 接口与规则骨架
  → 阶段1 地图/会话/计时/结果
  → 阶段2 物流/信标/门禁/撤离
  → 阶段3 截流器/倒地/救援/固有技能
  → 阶段4 六格/三选一/合成/掉落
  → 阶段5 全卡效果/私人信号/完整UI
  → 阶段6 交易/四契约/重连
  → 阶段7 回归/制图验收/平衡与发布
```

| 阶段 | 新增/接入文件（目录相对echo包） | 可验收成果与退出门槛 |
|---|---|---|
| 0 接口与纯规则 | `rules/*`、`state/*`、`EchoRoles`、`EchoBootstrap`；核对公共启动预检缺口 | N=6..12配额、胜负优先级、纯台账接口和37定义数据有单测；明确任何需获许可的公共接入改动，基类不改 |
| 1 模式承载 | `EchoGameMode`、`runtime/*`、`result/*`、`map/*`、`command/*`；公共入口一次注册 | 正常开局/预检拒开/中止；SAFE→作业；暂停/最后tick；正确结果快照与地图偏移；没有战斗也能调试完成一局 |
| 2 物流目标 | `action/*`、`objective/*`、`inventory/EchoResourceLedger`、`content/EchoParcelEntity`、最小HUD/交互反馈 | 真采集→交三枚→充能→钥匙核心→全信标→撤离；迟滞/稳流/助推走目标服务；无卡也可达，异常掉落实例不复制 |
| 3 机会制 | `combat/*`、`status/*`、`EchoCutterItem`、三身份RoleSkill | 两狼同tick命中、救援截止、控制抗性、强制/环境死亡、旁观语音、推挡与共享过载；不混入心形伤害 |
| 4 资源构筑 | `inventory/*`、`cards/EchoDraftService`、配方、背包/三选一界面 | 六格权威库存；1.5秒开包/10秒中断CD/20秒选择；品质保底、同系合成、KEY配额；重复包和满包边界通过 |
| 5 完整卡牌 | `cards/EchoCardEffects`、`signal/*`、`EchoDecoyService`、`client/*`、三语/图标 | 21基础+16高级逐卡七项测试全部实现；三种身份不同视角；假信号不改真目标；可用完整UI进行卡牌构筑 |
| 6 社交与恢复 | `trade/*`、`contract/*`、网络剩余协议、连接事件、托管 | 双方原子成交；四任务均可无随机卡达成；任务成功不抢停局；掉线/重连不刷物，正常结束可联合胜利 |
| 7 发布门槛 | 结果报告/回放适配、地图编辑工具与恢复日志、全部测试及回归 | 下述自动/多人/性能/普通模式矩阵完成；运行记录可重现，无占位卡/悬空配方；最终一次构建与资源检查 |

每阶段改动清单写明：新增类、已有接入文件、调用方向、阶段门控、清理入口、测试结果。发生接口缺口先定位真实代码；不在37张卡各自加mixin，也不为每局动态注册事件。

## 2. 自动测试设计

已有 `build.gradle` 使用 JUnit 5，可复用，无新依赖。纯规则层用普通Java集合、UUID、整数tick和可注入RNG，不为测试启动Minecraft全注册表。网络/实体/地图碰撞留给集成测试或手测，不在JUnit中伪造“已验证真实客户端”。

## 3. 多人功能验收脚本

使用独立测试服/调试世界，保留原运行服务器。用管理员调试工具定位边界时标记debug报告，不把强制给卡/快进所得结果当平衡数据。

| 场景编号 | 操作 | 必须观察 |
|---|---|---|
| M01 六人自然局 | 1狼4托运1中立；不调试给钥匙 | 2信标、3撤离，稳定基础循环；无人抽钥匙也能进核心 |
| M02 九人双狼 | 两狼同时迟滞、同时过载、同tick攻击一人 | 迟滞不叠加；仅一次关门；首次只倒地一次 |
| M03 十二人双中立 | 指定两不同契约，分别完成/失败，主局双方各赢一局 | 不互泄暗牌；一中立成功不抢停局；结果面板并列正确 |
| M04 构筑满包 | 六格满、两包堆、合成腾格、关候选页重开 | 不吃包、不重抽、不复制；快捷栏/副手不能绕六格 |
| M05 真伪信号 | 四种视角同时观察采集/声纹/伪造/雷达 | 授权接收者正确；假光不改真实HUD；旁观狼无私有情报 |
| M06 交易 | 满包交换、改价后旧确认、交钥匙再转手、偷报价锁定包 | 原子交换，无单边扣物；契约只按合法事实记 |
| M07 掉线 | 开包前/候选中/倒地/报价中分别断线，30秒内外重连 | 宽限一次、无新包/新保护；锁释放；候选截止不刷新 |
| M08 最后tick | 剩1tick完成最后信标、剩1tick完成第Q个撤离 | 分别完整撤离窗/托运者胜；已零时间动作不算 |
| M09 世界恢复 | 普通结束/管理员中止/写门后重启 | 门复原；孤儿实体不可捡；无对局自动续盘；恢复冲突不盖管理员方块 |
| M10 控制与语音 | 连续推挡、救援后保护、撤离/退场旁观、倒地呼救 | 抗性正确、保护不重复加；旁观频道隔离，倒地仍可听活人沟通 |

再覆盖7、8、10、11人数档的开局/自然终局；6/9/12是主要真人局，不意味着其它人数只做配额单测。每条记录服务器版本、规则hash、地图ID、人数/身份、事件顺序、预期与实际、回放/日志路径。

## 4. 普通模式回归与适配门槛

| 系统 | 回归点 |
|---|---|
| 谋杀/躲猫猫 | echo身份不进入默认候选；刀耐久、金币、击杀加时、超时胜负不改变 |
| 轮换/轮选/志愿者/换职 | 专属身份、卡代理不可被普通角色随机获得；原UI和技能键仍可用 |
| 职业名册与介绍 | 隔离分类可查看介绍，不进入可选池；其它身份筛选不被粗暴隐藏 |
| CCA与RoleData | 不增加每职业CCA；新局/换服清客户端投影，旧角色仍按原逻辑清理 |
| 地图与任务 | 普通图投票、重置偏移、initialItems、会议/场景任务保持原行为 |
| 网络与资源 | dedicated server无客户端类加载；类型只注册一次；未知协议有清楚报错；三语JSON有效 |
| 死亡与语音 | 普通死亡护盾/尸体/回放不改；模式倒地不能被默认死人频道误判 |
| 统计/结果 | 不污染普通谋杀胜率；模式报告全体UUID；hasWin在远端回放保存前已填 |

## 5. 初始平衡假设和调参方法

初值均集中在对应权威文件；这里只列调参关系：

| 观察指标 | 首轮假设/警戒线（非实测） | 优先调整而非加新系统 |
|---|---|---|
| 主阵营胜率 | 目标45%–55%，至少各人数档累计20局后再看；小样本只记现象 | 先看地图动线/蹲点，再调搬货减速、迟滞时长、充能速度 |
| 第一次核心进入 | 期望正式作业2–4分钟；频繁超过5分钟说明门槛过重 | 祭坛分散/可见性、补给周期与入口路线，不让钥匙只能靠稀有包 |
| 第一次倒地 / 救起比例 | 不要求固定击杀数；重点看首击后救援是否存在可行窗口 | 狼挥击CD、推挡、流血/救援时间、视线掩体；不叠血量 |
| 作业耗时 | 最终目标常在时限中后段完成，不能大量在2分钟无对抗完成或多数从不开门 | 晶体点距离/恢复、守点范围、迟滞时长，保持三枚一信标规则 |
| 物资密度 | 记录每人包获取/开包/未用卡与满包时长 | 箱刷新、奖励上限和权重；不新增商店或金币清库存 |
| 合成使用 | 各组有真实机会且不会高级卡碾压；不同人数分开看 | 同系基础卡权重与高级效能，而不是加跨系长配方 |
| 中立契约达成 | 各契约约35%–60%作起点，记录被迫无事可做的时间 | 确定性来源、走私路线、交易窗口和暴露；不把契约删到只剩刷包 |
| 过载价值 | 只有一次，能改变路线但不能所有正常局都无脑最后30秒按掉即必赢 | 门控点位置/LOS、撤离窗口、操作距离；保持不退已撤离 |

统计时排除调试/中止/重启局，同时报告排除数；胜率按主阵营和中立分开，不用“总赢家人数”混算。每轮只改一组相关参数，保存hash与理由，至少再观察一轮；不要一次同时改Q、狼数、迟滞和移速而无法归因。

## 6. 性能验收

在12人同时守点/迟滞/拆包/交易的实际地图压测，记录新增tick耗时、S2C包数/字节、地面实体与诱饵数、GC和客户端帧时间。目标新增模式逻辑p95<2ms/tick、公共目标更新<=2Hz/接收者、常驻资源实体<=256、诱饵<=24；这些是预算，未经测量不写“性能已通过”。

对比相同服务器/地图无模式逻辑的基线；区分声音播放与网络包数量。粒子在客户端摆形状，不能为拿到低CPU数字而把发包成本藏成每粒子一个包。超过预算先减少查询/同步频率和合并效果，不直接裁掉交易或中立玩法。

## 7. 发布完成定义

1. 11份文档中的每个首发机制有对应实现/测试或明确的获批变更记录，卡池无TODO占位。
2. 自动测试和阶段完整构建通过；多人矩阵与普通模式回归有实际记录；每档人数均能正常完成主局。
3. 资源所有权守恒、一次性奖励/过载/结算幂等、私人同步不外泄、重连与恢复不复制资源。
4. 真实地图具备可行的开放→核心→撤离路径；坏配置在玩家状态/世界被破坏前拒开，异常中止不污染战绩。
5. 文案/资源/命令帮助三语完整；核心基类、版本号与依赖未被擅自改动。
6. 结束后门体、模式工具、声光投影、速度/禁用效果、锁与语音均清干净；下一局不继承旧matchId。
