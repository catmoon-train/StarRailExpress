# 回声托运站：实现方案索引

> 状态：完整目标方案，分阶段实现中。适用：StarRailExpress 当前 Fabric 1.21.1 / Java 21 架构。文内数值是首轮测试基线，不是实测平衡结论；01–10中的拟新增能力以实现进度为准。

> 已开始分阶段编码；实际已实现内容、验证记录及开发开关见 [实现进度](IMPLEMENTATION-PROGRESS.md)。下列01–10仍是完整目标方案，不表示全部功能已经完成。

## 1. 一句话玩法

6–12 人在托运站中采集晶体、争夺核心区钥匙、启动信标并撤离；截流者靠截货、迟滞充能和一次封门阻止物流，投机客靠个人契约独立获胜。六格背包里的三选一和同系列合成，提供每局不同的构筑，而不是额外增加经济规则。

**模式 ID 定为 `noellesroles:echo_freight`，代码主包拟为 `org.agmas.noellesroles.game.modes.echo`。** 本目录中除明确标注“已有”的类名、字段、包和配置外，均为拟新增设计。

## 3. 术语

| 中文 | 稳定标识 | 含义 |
|---|---|---|
| 托运者 | `CARRIER` | 主阵营逃脱方；不是普通模式平民职业池 |
| 截流者 | `INTERCEPTOR` | 主阵营阻截方；可持专用截流器 |
| 投机客 | `BROKER` | 中立；个人契约不改变主阵营胜负 |
| 作业 / 撤离 | `OPERATIONS` / `EVACUATION` | 两个互斥计时阶段 |
| 倒地 / 已受创 | `DOWNED` / `WOUNDED` | 首次命中待救 / 救起后仅剩一次机会 |
| 已撤离 / 已退场 | `ESCAPED` / `RETIRED` | 托运者离场 / 已成功投机客自愿离场；不是死亡 |
| 基础 / 高级 | `BASE` / `UPGRADED` | 合成等级；与普通/稀有品质正交 |
| 物资包 | `SupplyPack` | 普通、稀有、黑市三种；未开包也占背包格 |
| 资源实例 | `instanceId` | 一份可移动资源的 UUID；与定义 ID、槽号分开 |
| 对局时钟 | `matchTick` | 暂停时不推进的模式逻辑 tick；不是网络收到时间 |
| 结果快照 | `EchoResultSnapshot` | 停局前冻结的全体参与者结算事实 |

## 4. 相比原稿的明确修订

| 原稿缺口或冲突 | 本方案决策 | 原因 |
|---|---|---|
| 11 人中立数在表格与正文不同 | 6–11 人一中立，12 人双中立 | 沿用人数表，配额和总人数一致 |
| 同系列合成却举跨系列例子 | 只做同系列两张基础卡合成 | 无需记跨系配方；所有系列都有唯一产物 |
| 卡池标签与系列列表不同 | 按 05 的闭合集合注册 | 不出现抽到却无配方的悬空系列 |
| 狼必有一次关门，又是稀有卡 | 改为截流阵营共享一次固有技能 | 双狼不会变成两次；胜负不依赖能否抽中 |
| 卡牌加心形伤害，但死亡按次数 | 猎杀标记改为暴露与减速 | 沿用有效致命命中，不引入另一套血量 |
| 12/14 分钟与完整撤离窗矛盾 | 作业 12/14 分钟，成功后另给 90/120 秒 | 作业最后时刻完成也获得完整撤离机会；最长 13:30/16:00，不含安全准备 |
| 钥匙可能耗尽或被永久囤积 | 确定性补给、核心免费出口、钥匙有权威台账 | 狼能拖延，但不能靠藏钥匙让必需信标永久不可达 |
| 中立交易依赖抽中交易卡 | 近距基础交易免费，卡牌扩大交易能力 | 每种契约都能不靠随机卡完成 |
| 中立一成功可能提前结束全局 | 契约成功锁定，主局继续 | 与联合胜利一致 |
| 商店与角色系统可能串入 | 独立模式，只分配三个专属身份 | 构筑取代普通职业堆叠，不恢复旧修机模式 |
| B 键可能冲突 | 复用当前背包键及已有 G/右键 | 遵守仓库按键约定 |

## 5. 架构边界

已有且可复用：`GameMode` 生命周期、`SREGameModes.registerGameMode`、`RoleData`、背包扩展接口、统一 `RoleSkill`、`SREGameTimeComponent`、标准停局与回放、地图投票/Areas、Fabric 网络和粒子工具。证据路径与限制见 [06](06-server-architecture.md)。

需要新增：模式运行态、三身份、六格虚拟库存、卡牌定义与效果、引导与资源事务、掉落实体、信标/门禁管理、契约判定、按接收方同步和地图专属配置。**背包界面扩展不等于安全库存，旧修机参考包不等于已接入 API。**

`GameMode` 与 `SRERole` 基类保持不动。当前已同步的职业 ID 不是保密身份容器；本方案保证私人手牌、候选和契约不通过新增公有包泄漏，不宣称能防止修改客户端读取底层职业信息。伪装是正常客户端的表现博弈，详见 07、08。

## 6. 交付边界与验收

本目录不含可运行代码，不新增依赖，不修改旧文档或现有源码。后续交付应以 10 的阶段为准，每个功能块完成后统一测试。首个最小闭环只是开发里程碑；完整首发包含 05 全卡池、四种契约和安全交易，不能以“以后再做”代替。

完成判断：每个机制能找到规则、状态、失败处理和用例；每个拟新增公共协议能找到接收方与服务端校验；每个地图必需资源有确定性来源；原有模式回归通过后才可称为实现完成。
