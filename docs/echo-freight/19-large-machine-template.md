# 19 · 回声枢纽真正多格机器模板

本次只调整当前 **200×200×22** 枢纽模板、布局辅助类与回归测试，不重建地图风格，
不迁移或自动覆盖玩家已有地图；仍须管理员显式执行生成命令，沿用覆盖冲突确认流程。

## 真正占格，不是渲染放大

- 信标（含核心）、晶簇、黑晶采集点、祭坛：**3×2×3**，每台 18 个实心部件。
- 其余机器：**2×2×2**，每台 8 个实心部件。
- 根是正面左下角，`part = x + 3*z + 9*y`；小机器编号不连续，不能按 0..7 写入。
- 北 `(x,y,z)`，东 `(-z,y,x)`，南 `(-x,y,-z)`，西 `(z,y,-x)`。
- 每格都有真正的机器方块、相同 FACING 和对应 PART。Layout 的非根部件为
  `MACHINE_PART`，参与实心碰撞与路线检查；`machineAt` 提供所属根、种类、朝向与编号。
- 全图仍为 **33 个任务根点**，共 **404 个机器方块**（33 根 + 371 非根部件）。
  `markers()` 和侧文件只记录根，部件不增加任务数量。

纯布局的 `EchoManorMachines` 不初始化 Minecraft 注册表；映射测试把其尺寸、
全部部件和四朝向旋转逐项与公共 `EchoMachineStructure` 契约比对。

## 留位与坐标调整

所有机器根均位于局部 **y=4**。每台机器预留完整占地，以及覆盖整个正面的一格宽、
两格高站立通道。布局构建时拒绝侵入其他机器及其通道、出生/安全点、门体、
核心区域边界和撤离门楼；只清理必要的局部非墙装饰。点位数量、人数阈值不变。

| 调整对象 | 新根坐标 (x,y,z) | 朝向 / 原因 |
|---|---|---|
| 核心信标 | (100,4,73) | 北；与免费出口及其正面通道分开 |
| 东侧黑市箱 b2 | (104,4,78) | 北；全部留在核心区，避开角柱 |
| 西核心门控制台 | (90,4,67) | 西；从墙内移到门外走廊 |

其他机器根坐标保留，朝北。核心两扇门和撤离门的体积、核心区域、撤离检测区不变；
旧嵌墙面板恢复为完整墙体。控制台侧文件高度直接取真实根，不再使用旧 y=5。

## 生成与验证

冲突预览、模板写入与实战区复制统一调用 `EchoManorScene.state(layout,x,y,z)`；
复制不反读可能被编辑的模板半成品。保持 `UPDATE_CLIENTS | UPDATE_KNOWN_SHAPE`，
不添加邻居更新、自动结构扩建或旧图迁移。

回归覆盖：全部 footprint/唯一 part/唯一根、整幅正面站位、门体与出生安全点避让、
核心机器完全内收与边界封闭、四阶段路线（每扇核心门单独开、撤离门开，含往返及
可跳/不可跳）、6–32 人配置与数量阈值、侧文件根点坐标及 JSON 往返。

本次直接以 Java 21 `javac` 编译纯布局与配置代码，反射执行真实 JUnit 断言：
`EchoManorLayoutTest` **9/9 通过**。按要求未运行 Gradle；含 Minecraft 的映射契约测试、
完整项目编译及实际游戏内生成/交互验收由最终整体验证执行，不能用纯布局结果替代。

### 结构接口集成注意

`UPDATE_KNOWN_SHAPE` 只跳过邻居形状更新，不能抑制机器自身的 `onRemove`。
最终生成器已使用公共 `EchoMachineStructure.mutate(Runnable)` 保护模板/实战区批写。
分帧地形写入时先把机器格留空，地形完成后同步写齐全部 404 个部件，
避免旧结构连拆，以及半成品被定时完整性自检删除。
