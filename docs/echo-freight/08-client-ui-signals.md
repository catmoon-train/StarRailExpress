# 08 · 客户端界面、操作、信号与资源

> 依赖：[04 库存事务](04-inventory-draft-crafting-trade.md)、[07 协议](07-network-consistency.md)。本文件负责表现和操作，不产生第二套成功判定。UI 遵循既有 `docs/ui_style.md`，不新增 UI 库或按键。

## 1. 输入与入口

| 场景 | 操作 | 行为 |
|---|---|---|
| 打开模式背包 | 复用玩家已绑定的背包键，默认通常为 E | 原 `LimitedInventoryScreen` 通过身份扩展增加显著“托运背包”入口；点击打开独立 EchoInventoryScreen，保留 parent |
| 托运者基础技能 | 现有 G 技能键 | 推挡准星狼，客户端显示能否命中；服务器最终校验 |
| 截流者基础技能 | G | 撤离阶段申请共享一次过载；不是按键循环切卡 |
| 投机客基础技能 | G 对准玩家 | 发起基础近距交易，未命中不消耗 CD |
| 采集/提交/迟滞/救援/开箱 | 空手按住右键 | 发送 BeginAction，并每5 tick续约；松手/目标变化取消；救援距离用02例外 |
| 狼攻击 | 持快捷栏0截流器按住再松右键 | 服务器物品使用链，最小蓄力与挥击 CD 由02规定 |
| 主动卡自用 | 背包点“使用” | 发一次 UseCard，自用不需要世界瞄准 |
| 主动卡对世界/人物 | 背包点“装备”→关闭面板→切快捷栏1通用代理→右键目标 | instanceId 保存在本人私有选中状态，代理 ItemStack 不存真实卡 ID/参数 |
| 两点卡 | 装备后连续右键两点，第二点后提交 | 第一落点只是客户端预览，不扣卡；ESC取消预选，服务器对两点一次校验 |
| 合成 | 拖一张到同系卡上或选两张后“合成” | 展示确定性结果并确认；触屏/不熟拖拽者可用按钮替代 |
| 交易 | 背包“向准星玩家交易”或投机客 G | 报价/确认，不打开传统商店 |

不直接替换所有 `LimitedInventoryScreen`，不对其新增 mixin。三身份共享 `EchoInventoryScreenExtension` 工厂，initTail 挂入口，render画简要货物/契约；独立 Screen 复用同一 private projection。可选 `/sre:echo_bag` 客户端别名挂到现有 `SREClientCommand`，只给当前模式使用。

工具不占六格，但也不能挪入副手、容器或丢弃。服务器进入模式发代理，结束回收；服务器模式工具 use()/useOn() 检查当前身份和 matchId，普通模式持有代理只显示不可用，不执行卡牌。

## 2. 背包布局与交互状态

```text
┌ 回声托运站 · 身份 · 当前阶段 · 剩余时间 ┐
│ 货物 ○ ○（物流卡可扩到四槽）  钥匙提示 │
│ [槽1] [槽2] [槽3]  │ 卡牌/包详情         │
│ [槽4] [槽5] [槽6]  │ 使用 / 装备 / 丢弃  │
│ 合成预览 / 与准星玩家交易               │
│ 本人契约或团队目标 · 网络状态 · 返回    │
└─────────────────────────────────────┘
```

六格必须视觉固定且明确编号，包标品质和“×2”，被动标“占格生效”，跨阵营卡标“不能使用，可交易”，钥匙标个人一份上限；高级卡显示等级图标，品质颜色不代替文字。货槽不是可放卡的额外两格。

| 状态 | 必须表现 |
|---|---|
| 初次数据未到 | 同步中，所有写按钮禁用；不拿空数组显示“背包丢了” |
| 空格 | 空格边框；能接合法拖拽，不接普通 ItemStack |
| 开包预留 | 锁形与“选卡保留”；不能拖入别的卡 |
| 引导中 | 1.5秒条、移动减速提示、取消按钮；关屏会取消并提示10秒CD |
| 候选可选 | 三张同时完整显示，倒计时20秒；候选0有“超时默认”小标；关屏不会重抽 |
| 交易锁定 | 锁图标、所属交易，不能用/丢/合；可以取消交易解锁 |
| 请求已发送 | 禁止重复点击，不本地先删卡；回复后再更新 |
| 版本冲突 | 结束当前拖拽，显示“背包已变化，请重新选择”，取本人快照，不自动重复提交 |
| 倒地/受控/SAFE/暂停 | 对应禁用原因；倒地可查看，已 OFFERED 按04例外允许选择 |
| 中立已成功 | 显示“个人目标已锁定；可继续或到退场点离开”；拾荒者只显示“等待存活结算” |

选择开包候选不要求危险确认；丢弃卡牌、最终退场需要确认。拖拽只作预览，放下才请求；跨系合成红色预览并说明原因，不能静默吃卡。移动槽位失败恢复服务器最新布局，不把旧拖影留在鼠标上。

## 3. 三选一与交易面板

三选一单卡展示：图标、名称、系列、品质、效果核心数字、是否能同系合成及当前拥有同系数量。不得通过悬停去请求服务器重抽。窄屏仍同屏三卡，可压缩图标与换行；至少支持320×240逻辑分辨率。超时自动选择已由服务器处理，客户端不能本地直接发放。

交易面板左右各两个报价槽，中间明确“交换后占格 X/6 / KEY容量”，底部两个独立确认标记、报价版本与剩余秒数。对方报价变更时立即取消本人的绿色确认态；“确认”文字明确不是无条件接受未来修改。对手阵营颜色按当前表现渲染，不显示真实阵营或契约；报价资源的使用限制可以展示。

距离/视线不满足持续提示并等待服务器取消；服务器一旦取消关闭可写控件，保留简短原因。取消不会丢物；动画不得让用户误以为已经成交。10/16格增强提案在创建后显示其本笔有效范围。

## 4. HUD 与世界指示

- 顶部：阶段+时间；下方2/3个信标：`已交/3`、充能%、封锁/暂停剩余；撤离期改为 `已撤离/Q` 与门状态。
- 左下：本人货物、钥匙脉冲下次时间、生命状态；受创使用明确裂纹图标，不加另一套心数。
- 右下：G固有技能及冷却/过载共享次数；当前装备的虚拟卡，不显示私人完整手牌。
- 中央准星：可交互对象、所需动作与拒绝原因；引导条只一个；倒地显示45秒流血和呼救，不把整屏锁死不让观察。
- 中立目标仅本人看；主目标和中立目标分栏。旁观模式 HUD只看公开目标与已发生事实，不额外解锁活人手牌/暗牌。
- 显示倒计时以服务器 tickBase和同步偏差本地计算；暂停停止动画进度。低TPS时不能按现实秒提前播放“成功”。所有会改变结果的标识等服务器确认。

已有普通角色名、本能颜色、金币或心情 HUD 对本模式门控隐藏；通过现有 `OnRenderRoleName` 等客户端事件和角色配置接入，若没有对应抑制钩子，在接入清单中列明具体缺口，不能只是画新 HUD 盖住旧 HUD。

## 5. 信号可见性矩阵

下面是信号范围和接收者的权威表现规则；主时间和周期由03/05决定。仅在同一模式地图/维度内传播，“全图”不包含大厅或另一世界。

| 信号 | 谁听/看见 | 内容与时长 | 可否被静默/伪造 |
|---|---|---|---|
| 普通采集 | 24格内任何在线活人听；16格内普通粒子 | 开始轻声、结束一次晶体声；不逐tick播 | 静默压制这次声光 |
| 搬运回声 | 48格内站立截流者 | 每20秒一次八向扇区/边缘波纹，显示1秒；不发货主精确坐标/姓名 | 静默采集不压制；假人仅按05误导技能嗅探，不伪造真实周期台账 |
| 钥匙脉冲 | 48格内截流者（含携钥狼自己之外的狼） | 每15秒一次方向脉冲1秒 | 双面面具可抑制本人一次 |
| 提交回声 | 全图活人听，信标高亮10秒 | 声源真实提交信标，公共数字按真实更新 | 本次可静默；假提交仅声/光不改数字 |
| 充能 | 32格内可见光柱，16格内持续低鸣 | 充能期间；ACTIVE爆发一次 | 不被静默；无高频粒子网络循环 |
| 迟滞开始/成功 | 24格内声音与粒子；公共HUD看真实迟滞 | 引导/成功各一次 | 可伪造视觉但不能改变HUD真实迟滞 |
| 拆包 | 16格内活人 | 开始一次拆封声，持续引导不用每tick发 | 不被静默采集器压制 |
| 交易成交 | 双方明确提示；16格内听一次成交声 | 不向附近公布交易物和真实阵营 | 无免费验明身份 |
| 黑晶提交 | 48格内活人听独特声 | 每次一次，不公布暗牌名称 | 不能静默；假回声不计契约 |
| 拾荒达标微光 | 32格内截流者 | 每15秒一次微光2秒，附目标轮廓授权不超过2秒 | 面具不抑制 |
| 钥匙契约使用 | 48格内截流者 | 增强方向脉冲2秒 | 这次任务暴露不被面具抑制 |
| 雷达/猎杀/黑晶嗅探 | 仅05列出的接收者 | 限时授权或八向扇区 | 由服务端真实目标裁剪 |
| 门开/过载 | 全图活人收到状态提示；32格门机械声 | 门体表现与真实碰撞一致 | 不伪造主撤离门状态 |

被淘汰/已退场者只听公开环境与旁观频道，不把仅狼声纹包发给旁观狼当场外情报。客户端收到权限到期、目标失效或会话结束立即清轮廓；不用全局发光药效泄漏给所有人。

## 6. 视觉风格、资源与翻译

遵循 `docs/ui_style.md` 的棕黑背景、米色正文和金色强调；托运绿、截流红、投机金只作身份主题。使用现有 SreButton、SreTabButton、SREPanelStyle；面板宽度min(700,0.9×width)，高度按屏幕clamp，滚动内容scissor。`renderBackground` 画背景，`render` 开头调用 super.render，之后画必要说明；避免背景压住控件。

拟新增客户端主包 `...echo.client`：`EchoClientState`、`EchoClientBootstrap`、`EchoInventoryScreenExtension`、`EchoInventoryScreen`、`EchoDraftPanel`、`EchoTradeScreen`、`EchoHud`、`EchoSignalRenderer`、`EchoParcelRenderer`。common代码不导入这些类。

| 资源 | 路径/键规范 |
|---|---|
| 通用文案三语 | `src/main/resources/assets/noellesroles/lang/{zh_cn,zh_tw,en_us}.json`；`echo.ui.*`、`echo.hud.*`、`echo.error.*`、`echo.contract.*` |
| 模式名 | `hud.sre.tip.gamemode.echo_freight`，供已有 GameMode.getName 查找 |
| 角色名/目标 | `announcement.star.role.echo_carrier/interceptor/broker`、对应 goals；详细介绍写入 role_modifier_intro 三语文件 |
| 每卡文案 | `echo.card.<ID>.name`、`.desc`、`.series`（系列也可引用共享系列键），描述参数不硬编码到绘制代码 |
| 工具物品说明 | `item.noellesroles.echo_cutter`、`echo_card_proxy` 及 `.desc`；描述写入现有 item_intro 三语文件 |
| 图标与掉落贴图 | `assets/noellesroles/textures/gui/echo/cards/<ID>.png`、状态/包/晶体图标；原生模型JSON可复用已有原版材质作开发占位，发布需有可区分图标 |
| 音效 | 优先复用已注册 Minecraft/SRE SoundEvent；新增音源才补 sounds.json，不能引用归档修机已删的音效常量 |

主要错误键集合：`FULL、CARGO_FULL、KEY_LIMIT、WRONG_FACTION、WRONG_PHASE、PAUSED、DOWNED、CONTROL_IMMUNE、OUT_OF_RANGE、NO_LOS、BUSY、LOCKED、NO_TARGET、COOLDOWN、REVISION_MISMATCH、STALE_REQUEST、INVALID_SESSION`，实现时映射 `echo.error.<snake_case>`。所有禁用按钮可悬停说明原因；不只用颜色表达。

## 7. 客户端验收

GUI逻辑分辨率320×240、640×360、960×540，GUI缩放1/2/3/4，窗口尺寸变化和中英繁体长文案均不溢出；三选一和确认按钮始终可达。ESC优先取消拖拽/两点预选，再回父屏；关候选页不取消offer。

分别用托运者、狼、中立、旁观者观察同一信号，检查权限和清理；模拟500ms回复延迟不重复扣卡、不本地提前成功。连开背包20次不重复注册事件、不累积控件；普通模式界面与按键不受影响。

## 8. 开发实现增补记录

37张独立图标与三选一/详情滚动已接入。卡牌说明现在使用无默认数字的机制文案+冻结规则参数表，避免自定义数值后仍显示旧秒数。首次绑定/重连单独同步规则，规则未到禁用写操作。

公共目标HUD与本人私有状态分离；本人引导、短期拒绝提示和KEY原周期截止已同步。进度封顶99.9%，服务端清理/成功事实才结束，不由本地满条发奖。普通身份/金币/心情/旧时间栏在共用渲染入口按Echo模式门控，公共回调/广播保留。

截流器和代理工具已替换独立贴图，假影按实际宽臂/细臂皮肤选择缓存模型。全图真/假提交声音共用有界位置包和固定音源，客户端显式无衰减且保留真实位置，不使用听者坐标模拟方向。以上均未替代第7节的实际游戏验收。
