# 04 · 六格背包、三选一、合成与交易

> 本文是模式库存与资源事务的权威来源。卡定义和配方见 [05](05-card-catalog.md)，协议见 [07](07-network-consistency.md)。这是拟新增虚拟库存，不是限制原版槽位显示就算完成。

## 1. 唯一库存与实例

六格 `EchoInventory` 保存在当前身份 `EchoRoleData` 中，仅本人同步。普通/黑晶在独立货槽，见 03。快捷栏的截流器与通用卡牌代理只负责输入，不是可交易资源，不占这六格。

| 内容 | 每格容量 | 是否能交易/丢弃 |
|---|---:|---|
| 未开普通/稀有/黑市包 | 同品质最多两包；每包有独立 packId | 未被绑定/占用时可 |
| 基础/高级卡 | 一张，不叠 | 可；不允许使用跨阵营卡 |
| 声纹钥匙/万能钥匙 | 一份，所有 KEY 合计每人最多一份 | 可；掉落规则见 03 |
| 被动卡 | 一张，占格自动生效 | 可；离格立刻失效并处理超额货物 |
| 保留槽 `RESERVED` | 无资源，显示开包占位 | 不可交易、手动挪动或塞入资源 |

每个资源实例包含 `matchId、instanceId、definitionId、kind、tier、originEventId`。包另有质量、首次绑定所有者和候选状态；钥匙另有合法交易来源；地上实体只保存 `matchId+dropId` 并从服务器台账取资源。**同一实例只有一个权威容器**，UI、代理 ItemStack、掉落显示都不得拥有第二份可写卡牌。

槽号只是定位提示，最终总按 instanceId 和版本复核。原版数字键、Shift 点击、副手、Q、创造复制和合成网格不能操作虚拟实例；反之原版物品也不能转化为卡牌。不允许从资源名或 ItemStack NBT 直接创建合法实例。

## 2. 物资包供给

| 来源 | 品质 | 去重键 / 限制 |
|---|---|---|
| SAFE 开局 | 普通一包/人 | `matchId+uuid+starter`，重连不补 |
| 开放物资箱 | 普通一包/次 | 初始就绪，搜寻 2 秒，成功后 90 秒恢复；整箱全局共享 |
| 普通晶体采集 | 10% 额外普通包 | 一次已提交的采集事件最多掷一次；取消不能掷 |
| 成功救援 | 普通一包/目标 | 同一被救玩家本局仅一次奖励 |
| 首次向某信标交货 | 稀有一包 | 每玩家每信标一次 |
| 首次进入核心 | 稀有一包/人 | 从合法入口实际跨入才发；不重复触发 |
| 狼首次击倒某目标 | 稀有一包 | 每狼阵营每目标一次，不因两狼参与翻倍 |
| 首次迟滞某信标 | 黑市一包 | 全局每信标一次 |
| 核心高价值箱 | 黑市一包/箱 | 每局一次，搜索 3 秒；不依赖再次刷新 |

成功奖励装不下：先在同品质可叠包格合并，否则放空槽，否则在玩家合法点生成掉落；只有奖品落地/入包成功才登记奖励已发。实体生成失败进入短暂服务器待交付队列，重试不得重掷包品质或重新触发契约，结算前未交付只记录异常，不反复补偿。

地图开放物资箱下限：6–7 人六个，8 人八个，9–12 人十个，均初始就绪且 90 秒重生。因此拾荒者除开局一包外至少可从两个确定性箱拿包；“有来源”不保证在其他玩家竞争下自动成功。箱产出全局资源，不为每名玩家各刷一份。

## 3. 开包状态机与槽位预留

```text
UNOPENED
  → CHANNELING（30 tick，预留额外一个空槽，首次生成服务器候选并绑定本人）
  → OFFERED（消耗包，三候选可见；20 秒内选一）
  → RESOLVED（卡进预留槽；其余候选注销）
CHANNELING → UNOPENED_BOUND（取消，候选缓存不变，10 秒冷却）
```

### 3.1 开始

站立、非暂停、正式阶段，包归本人且未被交易/其它开包锁定，至少一额外空格。即使只剩一包、稍后会腾出该包格，**现在没有额外空格也不能开**；规则保持原稿，不做单包例外。每人最多一份未完成的绑定包，取消到 UNOPENED_BOUND 后必须先继续这包，不能另开一包囤候选与配额。

首次开始时以服务端 RNG 为这包固定三候选（不发给玩家），记录绑定者、候选与 `offerId`；禁止绑定后的包交易、偷取或手动丢弃，防止跨阵营洗候选。包堆不为绑定而额外拆格，只锁选中的 packId；引导期间该格不能操作，另一包仍保留其独立 ID 和未绑定状态。候选任一位置含 KEY 就为整组预留一份本人/全局 KEY 配额，从首次绑定至解决/作废保持；本人此时不能另拿 KEY，避免重开时原候选失效。

预留空格后开始 1.5 秒引导，施加移动 -50%并发出 16 格可听拆包声；可移动/转向，不能跳跃、攻击、用卡或再发起资源动作。关闭屏幕取消引导，包不丢，预留槽释放，进入 10 秒冷却；重开仍是同包同候选。受控、倒地、掉线等取消相同。

### 3.2 提供候选与选择

引导结束重校验包、保留槽及玩家状态，将包移为 `CONSUMED_BY_OFFER`，发送本人三候选，预留槽保留。包堆从两包变一包保持原格；单包移走后释放原包格，但不替换原先预留的输出槽。

OFFERED 允许走动，禁止其它虚拟库存写入、用卡、合成和交易；防止抽到钥匙后自己又捡钥匙造成候选不可选。关闭屏幕仅隐藏候选，重开仍显示原 offer 和剩余时间，不恢复已耗包。20 秒不选自动选候选 0；不会因关闭/重连续时。任一候选含 KEY 均已预留一份配额，不只检查候选 0；选非 KEY 时释放预留，选 KEY 时将预留原子转换为实际持有。

被击倒不取消已完成拆包的 offer；倒地可只读查看，选卡/自动选卡的入包事务仍执行，不能使用。若本人最终淘汰/主动退场/撤离/宽限到期，先解决 OFFERED（默认 0）后随库存掉落；尚未完成引导的 UNOPENED_BOUND 则作废该包、缓存与 KEY 预留，不产卡、不计开包，堆里另一未绑定包正常掉落，避免留下永远绑定离场者的资源。主局结束将未选 offer 和绑定包关闭，不为了在结算瞬间刷三包任务而自动计数。正常手选/超时自动选完成才产生一次 `PackResolved`，每 packId 一次。

## 4. 抽取算法

先限制“本局启用 + 本阵营抽取池 + KEY 配额”，再按品质和定义权重抽取三个**不同 definitionId**。同系列两张不同基础卡可以同一组出现；不许相同定义三连。即时目标不存在不从池中删卡，避免探知附近狼/信标状态。

| 包品质 | 候选 0 的品质 | 候选 1、2 各自品质 |
|---|---|---|
| 普通 | 普通 85%、稀有 15% | 普通 85%、稀有 15% |
| 稀有 | 稀有 100% | 普通 70%、稀有 30% |
| 黑市 | 稀有 70%、史诗 30% | 普通 50%、稀有 40%、史诗 10% |

普通/稀有是卡品质，不是合成等级；高级卡为史诗，仅黑市可直接抽，或由合成获得。品质桶内按 05 的整数权重无放回抽样，不能拿配置顺序当权重。

桶抽空时优先向低品质回退（史诗→稀有→普通；稀有→普通），若回退会破坏候选 0 保底则本次开包拒绝，不耗包。初始化校验要求每阵营至少三种可抽定义，至少一个稀有和史诗；正常首发池无此问题。客户端不能指定品质、随机种子或候选 ID。RNG 按用途分流，取消交互不干扰钥匙初始位置或身份分配。

## 5. 合成与被动

配方键为 `recipeGroup`，通常为“阵营+系列”；通行组 `SHARED:ACCESS` 可供三阵营合成。两张不同实例、同 recipeGroup、同为 BASE、都可被合成者使用，合成一张唯一 UPGRADED 产物。**两张完全相同的卡也可合成；跨系列、不同阵营专属卡、任何高级卡都不行。**

服务端先建立结果预览，再在收到确认后一次性：校验两实例和 inventoryRevision → 取走两个输入 → 在较小槽号放新实例 → 另一格为空 → 清输入绑定/被动 → 更新属性与超额货物 → 发成功事件。无需第三空格；全满背包也能合成。不随机产出，不继承旧实例 ID；钥匙交易来源在合成时失效。

同类物流被动取最高等级，多个不叠容量/减速。被动在 OFFERED 的预留槽不生效，必须正式入包；交易锁定仍在原包、效果继续直到成交移走。失去被动令货槽溢出时按 03 丢多余晶体，不丢玩家其它卡。

## 6. 丢弃、拾取、资源回收

- 卡/包在 UI 选“丢弃”后确认，脚边生成掉落；钥匙不弹危险确认，仍遵守服务器不可销毁规则。活跃交易报价中的资源、绑定包与保留槽不能丢。
- 地面卡/包拾取是 2 格内 LOS 的明确操作，不走原版自动碰撞拾取。先验证容量、KEY 上限与资源所有权，再注销实体；满包保留地面资源。
- 拾取跨阵营卡有“不可使用，可交易”的提示，不自动换成自己的卡。只有包在首次拆开时按开包者阵营生成候选。
- 普通卡/包掉地 120 秒后注销；关键钥匙/晶体走 03 回收，不能套通用销毁。模式地面资源实体上限 256，新增普通奖品超限进入待交付队列；关键货物优先回收，不静默删除。
- 合成、交易、偷取、倒地、淘汰和超时全走同一所有权服务。台账终态保留去重记录到本局结束，不能删完 tombstone 后让旧请求再次成功。

## 7. 交易协议

### 7.1 基础提案

所有站立玩家均能从背包发起，投机客也可 G 对准目标快速发起；基础范围 <=3 格、LOS，有效 20 秒，每人一次只参加一笔交易，发起者冷却 15 秒（提案发出即计，拒绝不重置）。交易卡提升距离/有效期，见 05；不影响双方必须真实确认。

每方可报 0–2 份资源实例（不是两个整堆），支持单向赠送，但情报贩子只计双向非空交换。普通/黑晶、已绑定包、代理工具、保留槽、已占用实例不能报价。卡牌阵营限制和钥匙上限显示在预览，服务器最终重算。

### 7.2 两阶段确认与原子成交

```text
PROPOSED → EDITING（报价版本 v）
  → A_CONFIRMED(v) + B_CONFIRMED(v)
  → COMMITTED
任一报价变动 → v+1，并清除两边确认
任一超时/离线/倒地/攻击/离距/LOS失效/取消 → CANCELLED
```

报价时将实例标记为锁定但不先扣物；一个包堆可锁其中一包，界面显示其锁定数量。每次修改确认双方只看到对方报价，不同步对方完整库存。距离和 LOS 持续校验；远距提案范围由创建时保存的增益规则决定，不在中途因 buff 到期突然变成基础范围。

成交时在服务器主线程一次性计算“各自移走报价后、再接收对方资源”的最终槽位，允许满包等量交换；检查 KEY 配额、不同包品质叠放、两边 revision、同一 matchId、仍站立在线且范围合法。全部条件通过才应用双方新库存和资源所有者，移除锁，写 `tradeId` 事实并同步两人。失败则零移动、零消耗、解锁并返回原因，不能先扣 A 再发现 B 放不下。

受击与成交同 tick，按 01 序号处理；前一个事件使后一个条件失效时不再成交。资源被偷取卡选中前必须确认未锁定，不能从报价锁里偷走。清理旧交易回调必须匹配 tradeId，不能误解锁新一笔。

### 7.3 契约防刷

交易完成事件保存真实双方 UUID/阵营、转移实例与 origin、两方非空标志。情报贩子对每真实阵营最多记一次，并拒绝已记入同对手的相同实例往返；契约系统不查询 UI 颜色。钥匙贩子来源记录只在真正 COMMITTED 时创建，取消/报价阶段不计。

## 8. 验收矩阵

| 场景 | 期望 |
|---|---|
| 六格全满只剩单包 | 开包失败，包保留；合成合法两卡可腾格 |
| 两包堆引导被打断 | 不少包、不泄漏候选；绑定和 CD 保留，保留槽释放 |
| 关闭候选页再打开 | offerId、候选和截止时间均不变 |
| 两次同选择请求 | 只产一张卡、一次开包事件 |
| 两张同定义基础卡 | 可以合成；同实例两次不行 |
| 满包一换一 | 使用成交后布局判定成功，不以成交前无空格错误拒绝 |
| KEY 在候选/报价/地面并发 | 配额预留与台账只认一个容器，不超每人/全局上限 |
| 报价后用卡/丢卡/偷包 | 被锁实例均不可移动；其它库存变动令确认失效或重新校验 |
| 拾荒者开到第三包但未选 | 未达成 ARMED；正常选卡事务提交后才达成 |
