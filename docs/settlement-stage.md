# 列车 MVP 结算舞台

## 配置与占地

在现有 `starrailexpress` 配置中新增：

```json
{
  "enableSettlementStage": true,
  "settlementStageX": -100000,
  "settlementStageY": 0,
  "settlementStageZ": 0
}
```

坐标为**当前对局维度中的舞台地板中心**。舞台会重建 `x±16、z±15、y～y+14` 的 33×31×15 区域（含清空内部），请为它保留专用区域，不要设在已有建筑中。服务器拒绝越界坐标和与登车区、游戏区、地图粘贴区/模板区重叠的舞台。这里只增加原版方块，无新增模组依赖，不改模组版本。

黑混凝土构成地板、四壁、顶盖，隔绝外界景物。前区为磨制黑石镜面舞台、后区为哑光黑地板（尸体区），台口一道黄铜镶边；灯光只用暖色灯笼（台口两侧落地灯 + 顶盖三盏吊灯），不使用海晶灯。侧墙内收一格做黑石立柱与黄铜腰线，给出纵深又不破坏外壳。每 tick 最多处理 1024 个方块，区块逐个加载。会话结束仅撤销本次新增的强加载票据，不删除舞台、不修改已有强加载票据。

## 流程与表现

1. 原对局正常进入 STOPPING，并执行原有结束事件/战绩/文字回放。
2. 在清除职业与本局击杀数前冻结角色、胜负、死亡、击杀、任务数和可公开事件。
3. 原停局重置完成、主状态成为 INACTIVE 后发送独立会话 PREPARE。观众全黑确认后，服务端才构建舞台、发送分片快照并传送。
4. 客户端必须同时取得完整快照、TELEPORTED、本人正确落点及周边区块，并稳定确认后发送 READY。只有服务端 PLAY 才推进演出，不以“收到结算包”当成传送完成。
5. 黑页斜切揭开，获胜者由丝线吊下、落地后错峰庆祝并逐渐收势。胜方最多两排错位合照：MVP 正中，存活者优先前排，已死亡者优先侧翼/后排；后排插在前排空隙中，两排均接地，不悬浮。正常 32 人内保持完整人物间距。落败阵营等胜方落地后（150 tick 起）才依次从后台上方自由落体，堆在**裸露的黑地板上**（不加围台方块）。
6. 漫画扉页使用纸白、墨黑、少量朱红。默认皮肤在黑箱内绘制列车窗框、固定网点和完整纸景内衬，地面采用低反差印刷接缝，脚下有分层软影，不改真实地板和碰撞。纸景侧壁位于真实立柱内沿前方（±13.25，立柱内沿 ±13.5），前墙和顶盖也封闭；移除舞台中间的大型深色斜切板，装饰收回后墙细腰线，避免露黑墙和大灰块抢占画面。已注册皮肤继续接管自己的布景。全景保留尸堆，特写用胜者与后台之间的纸板衬景遮挡，尸堆物理仍照常运行。
7. 回放只展示**与 MVP 相关**的事件，另保留开局与终局锚点，保留原始相对时间与翻译组件。事件涉及物品时，发起者以正常手持物尺寸握在右手。上半身使用髋部父变换，头、躯干、手臂、外衣、皇冠和道具一起弯腰/扭转，腿部保留独立接地坐标，避免躯干脱离双腿。
8. `SettlementPresentation` 是镜头、排版和强调效果的共享纯计算层：按包围盒八个角点与 UI 安全区取景，覆盖双臂、正常持物和皇冠。开场横移→稳定全景→MVP 扉页→语义分镜→合照闭幕。购买/任务保持稳定中景，关键事件之间至少间隔 40 tick 才切镜；关键冲突有短促边缘墨线与轻震，没有整屏爆闪。机位、注视点、FOV、轻倾斜同时平滑，最后 80 tick 合页淡出。
   胜者从 3.8 格高度快速下降：26 tick 开始，下降 30 tick、最多错峰 6 tick，最迟 62 tick（约 3.1 秒）落地。渲染与镜头共用 `winnerLift` / `winnerBounds`，庆祝、吊线收起与镜头跟随同步提前；不改变后台尸堆、MVP 海报和会话总时长。
9. 后处理使用轻度分阶明暗、边缘墨线和稳定暗部网点，保留皮肤/扩展布景颜色；移除胶片随机颗粒与色散。仍在最终主目标上运行独立链，不替换 Iris 管线。
10. 自然结束或跳过后恢复原模式、镜头与声音，回到大厅准备区的可站立位置（原大厅落点已在准备区则优先用原点）。原文字回放仍可查看。

### 扉页排版与事件动作

- 不再逐人铺姓名/职业双行卡。场上只为 MVP 与当前事件相关胜者显示最多 3 条单行短姓名（最大 78×12 UI 单位），移除长引导线；职业集中在固定的 18 UI 单位高信息栏，最多显示事件双方，未知/无参与者回落焦点或 MVP。职业栏与姓名面积上限不随总人数增长；完整演员身份仍保留在快照与原回放中。姓名保持镜头内固定槽位，事件人物离场后释放空位，已死亡胜者仍以 × 标记。
- 旁白按实际行数决定高度，长文本最大 16%；固定字号裁剪滚动。职业栏固定在字幕上方，无事件时在画面下缘，不遮人物安全区；开场标题改为居中紧凑横排，取消大纸框，镜头不再给四处散布的职业卡预留空间，人物充分填充画格。MVP 独立海报仍保留姓名、职业和战绩的大字排版。
- 购买采用轻抬手看物品，任务/门交互采用点头或小幅操作；交锋分挥击、投掷和施放，换职/复活采用转身/抬头。未知、开局、终局不再套用攻击手势。每个演员保留自己的动作事件，避免下一条回放串改尚未结束的动作。
- 捕获时仅为空文案/原始枚举名生成本地化兜底，合法回放/自定义组件保留。购买物品使用实际记录的 ID 与翻译；数量从 `itemUsed` 的第二个冒号后缀提取，费用只取明确记录的 `message`，不误用旧转换器把数量填入的 `StoreBuyDetails.cost`。公开边界、事件顺序、原局时间、快照协议和其他回放屏的购买过滤不变。

### 独立 MVP 海报与稳定性修复

- MVP 亮相改为独立红黑漫画海报：巨幅半透明 MVP 底字、固定姓名/职业/本局贡献/击杀/任务，右侧只绘制 MVP 本人的实际皮肤。模型侧身入画、抬手致意、定格后收势；窄窗口改为上下布局，不再把整排胜者挤在数据卡后。
- MVP 页职业名与阵营获胜文字加粗、提亮；宽屏优先使用 1.55 倍 UI 字号（原分别 .9 / .82），长文本在自己的宽度内适配。窄屏重新分配信息轨道，职业名、统计、获胜文案互不重叠，且不再隐藏阵营获胜文字。
- 人像在透明深度目标中绘制后合成，按真实 alpha 轮廓增加米白描边和暗色投影，不以放大模型冒充描边。目标最长边限制 1024，结束、跳过及资源重载时释放。`Sampler0` 绑定同步写入 RenderSystem 纹理槽，避免原版 `setDefaultUniforms` 将其覆盖为旧纹理。内层不使用全局投影备份，避免覆盖外层最终 GUI 的备份。
- 纸景使用专用不透明深度写入层并关闭排序，软影仍单独透明绘制。近景背板改为固定横向列车窗景屏风（高 3.6 格），低反差窗格、细腰线和少量朱红饰条取代跟随焦点移动的斜切空白板；继续遮挡后台尸堆，但不再横移抢镜。正面 z=3.25、背层 z=3.65，保留 0.4 格真实层距和升降入场，避免近共面透明交叉淡入。地面与软影层级也拉开，降低闪烁。
- 动作增加蓄势→3 tick 快速发力→短定格→收势；交锋镜头约 8.6° 小弧线与不超过约 1.9° 斜构图，发力时点才有短推/轻震。购买与任务不使用冲突蓄势，保留 40 tick 最小关键切镜间隔，不以持续摇镜或整屏闪白制造张力。
- 结算环境采用压暗的烟棕纸色与灰绿窗景，地面/顶盖/屏风分层降低亮度。UI 的底色 `SURFACE` 与浅色文字 `PAPER` 分开，名片、页眉、跳过签和标题卡不再使用大面积亮米白；MVP 海报红底改为深朱红至酒红渐变。人物皮肤、描边 shader 与动作运镜不随环境整体压黑。

### 胜负 HUD 衔接与 MVP 动画皮肤

- MVP 演出期间暂停原胜负 HUD 倒计时；自然结束或个人跳过后，立即显示原有「平民获胜」等胜负 HUD，保留原来的可见时长，不再要求按 Tab，也不重复播放结算音乐。
- 新增皮肤类型 `mvp_animation`、皮肤 ID `ender_dragon`（传说品质），皮肤管理新增「MVP结算动画」页签，使用现有皮肤解锁/发放与持久化系统。
- 按持有触发：服务端冻结结算时，只有本局 MVP 已解锁该皮肤才使用末影龙场景；其他胜者/观众持有不生效。未持有、MVP 离线、旧快照或未知皮肤均回落原舞台。
- 末影龙主题在原结算区域内搭建末地石地面、黑曜石柱，以原版末地天空纹理覆盖黑箱内壁；不切换真实维度。纯客户端龙模型在上空盘旋，胜者落地后周围淡入双层紫色死亡光束，并播放一次原版末影龙死亡音效。龙不加入世界、不运行 AI、不造成伤害；结束/跳过/断线清理本地对象。
- 实机仍需验收：默认/持有皮肤的 MVP、自然结束/长按跳过后 HUD、多人获胜紫光、龙盘旋构图、Iris 开关与音效隔离。

## MVP 与阵营

- 以模式现有获胜判定为准，不重新计算阵营胜负，也不发放额外奖励。
- 杀手贡献分 = 本局击杀数；其他玩家贡献分 = 完成任务数 + 击杀数。
- 只在获胜者中评选 MVP。同分先比击杀数，再按 UUID 固定顺序，避免遍历顺序造成随机 MVP。
- 只有一个独立获胜者时前排仅其一人。若原玩法明确允许多名中立/附带职业共同获胜，保留这些真实获胜者，不篡改原结算。
- 未参与本局且没有角色/回放身份的大厅旁观者不作为演出角色，也不参与 MVP。
- 同一份 MVP 判定会写入玩家统计（`totalMvps` 与该职业的 `mvpsAsRole`），舞台关闭时也照常统计；是否计入沿用职业模式的 `shouldRecordPlayerStats()`，离线玩家不写，重新开局不会重复计数。

## 隔离、跳过和状态约束

- 演出使用客户端独立玩家模型，支持宽臂/细臂皮肤。真实玩家、其他实体、手部和普通 HUD 不进入演出画面。
- 开始即停止已播放现场声音；演出期间仅允许演出明确创建的声音实例，SVC 的实体/位置/静态 PCM 接收均取消。PLAY 时按本地玩家本局胜负播放对应结算音乐：装配了登记结算音效的音乐盒就用它的胜利/失败曲，否则回落到默认 `ui.piano_win` / `ui.piano_lose`。事件音为舞台提示音，并非对局语音录像。
- 现有回放保存的是事件，不含逐帧位置、原始音轨或玩家录音，因此这是**舞台事件重演**，不是原场景录像。
- PLAY 后 5 秒才允许长按 Enter / 小键盘 Enter；连续 1.5 秒跳过。松开、失焦或心跳中断重新计时。每位观众独立跳过，不中断其他观众。
- 请求必须匹配 UUID 会话和服务端当前阶段。重复 BLACK/READY、提前 FINISHED、旧会话包不推进状态。
- 开始游戏、初始化、地图投票或通用模式投票前同步结束演出，再扫描准备名单。断线、维度变化、加载超时、服务器停止也恢复/清理。
- 登车人数通过参与组件同步舞台 UUID 集合，并与实际准备区玩家做集合并集，不能“总人数加上舞台人数”后又被另一个 HUD 覆盖；同一玩家不重复计数，opt-out 仍生效。舞台会话不写存档。

## 时间和网络

开场 320 tick；每事件 3～30 tick（按事件数量自动压缩，但不抽样、不截断）；结束留 80 tick。大量事件可以通过长按跳过。

快照每片最多 24000 个 UTF-16 字符（不拆 Unicode 代理对），最多 512 片；每位观众每 tick 最多发送 2 片。超过上限拒绝舞台而不是发送不完整回放。加载每阶段超过 600 服务端 tick 自动恢复。
