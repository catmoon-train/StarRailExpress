# 伪人事件：死亡后复活

- 仅伪人事件激活且本局处于 ACTIVE 时，通过 `OnPlayerDeathWithKiller.FINAL_EVENT` 登记真实死亡；护盾拦截、假死和已经被替换的伪人不参与。
- 每位玩家每局仅一次机会。等待 700 个游戏 tick（35 秒），若仍处于真实死亡状态，以 15% 概率在自己的房间复活，并立即通过正式 `replace(..., DEATH_REVIVE)` 入口被伪人夺舍：登记伪人修饰符、AI 和控制状态，不再恢复为玩家自由操控的普通复活。
- 提前复活、离线、换世界、事件失效或游戏结束会取消待处理记录。没有自己的有效房间出生点时不复活，不回退至其他人的房间。
- 复活成功后按玩家 UUID 清除当前世界中对应的全部旧尸体，不删除其他玩家的尸体。
- 计时放在当前局 `Session` 内，未注册独立的延迟任务。局末清理和新局重建显式清空旧队列；推进计时和执行复活前都核对当前 Session 身份、事件激活状态及 ACTIVE 状态，避免下一局执行旧计时。

## 验证

`FakeSteveDeathReviveTest` 检查 35 秒常量和 15% 概率精确边界，并通过源码回归检查覆盖最终死亡入口、自己房间校验、尸体 UUID 过滤、复活后调用正式夺舍入口、提前取消及跨局防护。后者不是 Minecraft 实机集成测试。
