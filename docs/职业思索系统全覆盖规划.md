# 职业思索系统全覆盖规划

> 本文是规划文档，不是实现记录。生成脚本：`tools/gen_ponder_plan.py`（只读语言文件，可重跑）。
> 数据源：`assets/role_modifier_intro/lang/zh_cn.json`、`assets/role_name_goals/lang/zh_cn.json`。

## 1. 目标

为所有正式职业补齐「思索（Ponder）」职业教程，并在 `RoleIntroduceScreen` 的入口按钮里可用。
教程文案逐句取自 `info.screen.roleid.<id>` 原文，不自行改写（见 `docs/PONDERER_NOTES.md`）。

## 3. 现有资产

| 资产 | 位置 | 说明 |
| --- | --- | --- |
| 场景 JSON | `assets/starrailexpress/ponderer/scenes/role_tutorial_*.json` | 现有 3 个：bartender / jester / recaller |
| 内容清单 | `assets/starrailexpress/ponderer/content/role_tutorials.json` | 场景索引，新增场景必须登记 |
| 结构 NBT | `assets/starrailexpress/ponder/<name>.nbt` | `role_tutorial_common` 可复用作通用房间 |
| 自定义步骤 | `PonderSreExtension.java` | 16 个：role_player / walk / teleport / key / skill / mood / render / disguise / vitals / currency / timer / effects / bond / panel / shop / domain |
| 入口 | `RolePonderTutorial.java`、`RoleIntroduceScreen` | 场景 id 前缀 `starrailexpress:role_tutorial.` |

入口按钮对所有职业常驻显示（`isPonderButtonVisible()` 只判断是否选中职业），点击时按 `role_tutorial.<职业路径>` 查场景；查不到只弹 `screen.roleintroduce.ponder.no_tutorial` 提示。因此**补齐场景 JSON + 登记清单即可自动生效，不需要为每个职业写 Java 入口**。

现有三个场景的角色定位：

- `bartender`：酒保：物品/护盾/毒药三段，模板级参考
- `jester`：小丑：阵营 + 疯狂模式皮肤切换
- `recaller`：回溯者：技能/传送/时间轴

## 4. 难度评估模型

按介绍文本命中的机制元素累加评分（基础 1 分），>600 字额外 +1：

| 元素 | 权重 | 判定词（示例） | 需要的补充 |
| --- | --- | --- | --- |
| 物品 | 1 | 开局自带、开局获得、开局持有、右键、手持 | 摆出初始/持用物品（create_item_entity + show_controls.item） |
| 商店 | 1 | 商店、购买、售价、金币购买 | 商店陈列（role_shop + 实际 ShopEntry） |
| 尸体 | 1 | 尸体、遗体 | 尸体实体（player_body + CustomName） |
| 面板 | 1 | 界面、查看、终端、笔记、记录在 | 文书/界面面板（role_panel 或 show_interface） |
| 叠加 | 1 | 透视、直觉、发光、高亮、san值 | 数值与透视覆盖层（role_vitals / role_effects / role_timer） |
| 技能 | 1 | 技能键、主动技能、被动、冷却、CD | 技能演示与键帽（role_skill + role_key） |
| 多人 | 1 | 绑定、追随、寄宿、潜入、附身 | 第二个玩家模型与关系（role_player.linkId + role_bond） |
| 形态 | 2 | 疯狂模式、形态、时刻、阶段、进化 | 多段落形态切换（皮肤替换，参考 jester） |
| 结构 | 2 | 地图、房间、井盖、水下、列车 | 专用结构 NBT（generate_ponder_structures.py） |
| 领域 | 2 | 领域 | 领域场景切换（role_domain） |
| 特殊 | 2 | 寄生、夺舍、做题、投票、复制 | 现有步骤表达不了，需新增 Java 步骤或降级为文本 |

分档：

| 档位 | 分值 | 含义 | 单条预估 | 数量 |
| --- | --- | --- | --- | --- |
| A | 1–2 | 极简（纯文本/单能力） | 0.5 小时 | 45 |
| B | 3–4 | 常规（技能 + 物品） | 2 小时 | 93 |
| C | 5–6 | 复杂（商店/尸体/多玩家/形态） | 4 小时 | 86 |
| D | ≥7 | 最难（多阶段/专用结构/无法直接表达） | 8 小时以上 | 42 |

合计预估 **111.1 人日**（按 A 0.5h / B 2h / C 4h / D 8h+ 粗算，不含结构建模与 Java 新步骤）。

## 7. 公共缺口与基础设施补充

按职业统计的共性缺口（做完前两批再动 D 档）：

- **结构**：`role_tutorial_common` 只够演示「站着的玩家 + 桌面物品」。提到地图/房间/井盖/水下/铁门/车厢的职业共 59 个，需要 3–5 套新结构（标准房间、列车车厢、门与走廊、墓地/尸体场景、水域）。
- **多玩家**：需要第二个（必要时第三个）玩家模型的职业 42 个，靠 `role_player.linkId` + `role_bond` 表达关系，模型要错开位置避免穿模。
- **形态/皮肤**：36 个职业涉及疯狂模式或形态切换，需要按 `getPsychoSkin` 取皮肤路径（参考 jester 场景）。
- **商店**：148 个职业有商店，`role_shop` 直接读真实 ShopEntry，但要确认条目不被配置裁剪。
- **尸体**：37 个职业依赖尸体交互，统一用 `trainmurdermystery:player_body` + `CustomName`。
- **无法直接表达**：31 个职业（寄生、夺舍、做题、轮盘、投票等）需要新增 Java 步骤，建议先降级为「文本 + 现有覆盖层」占位，再按热度补真步骤。
- **文案三语**：所有 `text`/`title`/`hint` 必须同时写 `en_us` / `zh_cn` / `zh_tw`；`en_us` 缺 18 条介绍（`abnormal`、`candle_shade`、`command_block`、`daywalker`、`echo_broker`、`echo_carrier`、`echo_interceptor`、`entity_303`、`entity_null`、`error_404`、`farlands`、`him`…），涉及这些职业的批次要先补英文原文再引用。

## 8. 单职业执行模板

1. 读 `info.screen.roleid.<id>`（三语），确定段落划分（每段一个功能，id 用功能名）。
2. 核对证据：`RoleInitialItems`、`ShopEntry`、`getPsychoSkin`、相关实体/方块 id。
3. 写场景 JSON：第一段 `show_structure` 开场，后续段落每个功能一段。
4. 时间轴自检：每条 `text` 后补足 `idle ≥ duration`，且每条文本用不同 `point`。
5. 三语补齐，`tags: []`、`customTags: {}` 不写 null。
6. 登记到 `content/role_tutorials.json`，跑 `verify_ponder_structures.py`。
7. 实机播放，确认 `loaded N scenes` 且无 `unavailable`。

## 10. 事件篇：三个事件条目的思索

`command_block` / `night_event` / `halloween_event` 不是可选职业，介绍只有十几行，但机制散在 `CommandBlockDirector`、`NightEvent`、`HalloweenRuntime` 与多个 CCA 组件里，**必须把源码与介绍对着读**才能写出不编造的文案。

三者共同点：改变的是「整局世界状态」（时间、灯光、天空、视野、职业池、刷怪），不是一次技能动作，而 Ponder 场景是离屏沙盒（`docs/PONDERER_NOTES.md:340-342` 已确认没有真实时间/雾/服务端组件），所以难度高于绝大多数职业。

| `night_event` | 中立事件，只改环境 | 万分比 `nightEventEnableChance`（默认 200）+ `/sre:night next` | 4 段 | 环境层（夜/雾/灯灭瞬变）、亡灵走位 | 3 人日 |

三者都已在 `ModRoles` 以「事件载体职业」注册（`EggRole` + `setEventNeutral(true)` + `setDefaultMax(0)` + `setHiddenForRoleRotation(true)`，`ModRoles.java:2243-2291`），不分配给玩家；介绍页的思索按钮对它们同样显示，目前点开会落「无教程」。

### 10.1 `command_block`（杀手事件）

**触发**：`CommandBlockDirector.prepare()`（`game/command_block/CommandBlockDirector.java:301-326`）按万分比掷骰，`NoellesRolesConfig.commandBlockEnableChance` 代码默认 `1000`（10%）；管理员可用 `/sre:command_block next` 强制下一局（`commands/CommandBlockCommand.java:16-32`）。仅 `SREMurderGameMode` 生效，与躲猫猫 / 邪恶战争 / TNT / 赌徒 / 发现 / 鹅鸭杀互斥（`CommandBlockDirector.java:1027-1034`）。

**流程**（`CommandBlockDirector`，会议冻结期间停表）：

1. 开局 `start()`（`:409-434`）：占满杀手位；标记 `ceil(原杀手×1.5)` 名平民为异常（`markAbnormals()` `:794-818`）；把一名平民改写成警长 Steve（`assignSteve()` `:530-552`）；在游玩区中心列上方 18 格生成 `noellesroles:command_block_marker`（8×8 碰撞箱、客户端自绘）并接管开场镜头（`sendIntro()` `:363-407`，音效 `END_PORTAL_SPAWN`）；标题 + 广播 + `BEACON_ACTIVATE`。
2. 每 60 秒改写一名异常：提前 1 分钟变中立空壳「异常」并只给本人发预览字幕（`beginPreview()` `:554-572`），到期正式转化（`convertNext()` `:591-621`），全场字幕 + `EVOKER_CAST_SPELL`（`announceBirth()` `:623-630`）。
3. 每 120 秒随机一个场地事件（9 种：关灯 / 换位 / 信号干扰 / 时间回溯 / 缄默 / 金币补给 / 曝光 / 封锁 / 命令注入，`FieldEvent` 枚举 `:1036-1071`），触发前全场预告「即将发生：xxx」（`announceNextEvent()` `:824-833`）。
4. 每 75–112.5 秒在任务点旁刷新一道 `noellesroles:command_block_crack`，只有杀手看得见发光；好人用近战武器击碎 → 破坏进度 +1（`:469-472`、`addDestruction()` `:835-844`）。
5. 结束：破坏进度达到配额 `ceil(原杀手×1.5)+2`（`CommandBlockRules.destructionQuota` `:24-27`）乘客胜；否则时间耗尽或中立独立胜利（`filterEnd()` `:210-232`）。
6. 表现层：破坏进度 + 事件倒计时双条 HUD（`CommandBlockProgressS2CPacket`，客户端 `CommandBlockProgressClient`）；天空 / 雾 / 天光 / 月亮染紫（`mixin/client/roles/command_block/CommandBlockSky*Mixin.java`）。

**演示分段（建议 5 段）**：

| 段落 id | 内容 | 关键元素 |
| --- | --- | --- |
| `event_start` | 紫天、屋顶上空的巨型命令方块、开场镜头与广播 | 新结构（开阔车顶/机房）+ 环境层染色 |
| `abnormal` | 平民被标记异常 → 私发预览 → 全场字幕改写为池内杀手 | 两名玩家模型 + 顶部字幕 + 职业改写 |
| `crack` | 裂缝刷新、只有杀手看得见发光、击碎后进度 +1 | `command_block_crack` 实体或粒子近似 + 双条 HUD |
| `field_event` | 抽 2 个代表事件（关灯、换位）演示 | `set_block` / 模型换位 + 预告文本 |
| `settle` | 配额与胜负判定 | `role_state` 进度条 |

**改写池（15 个，`CommandBlockRules.pool()` `:89-95`）**：`stone_man`、`him`、`error_404`、`dream`、`entity_303`、`entity_null`、`farlands`、`white_eyes`、`stringer`、`fog_guest`、`paper_doll`、`mustard`、`pendulum`、`candle_shade`、`dreadlord`。其中 `pendulum` 及其余「Command_Role」职业**只能**由本事件产生（`ModRoles.java:2293-2501`），介绍文本与代码一致。

**缺口**：无天色/雾/天光步骤；双条 HUD 只能用 `role_state` 近似；同段落内换职业需要多个 `role_player` + `linkId` 替换；裂缝是非方块几何体（先用 `spawn_particles` 降级）。

### 10.2 `night_event`（黑夜事件）

**触发**：`NightEvent.prepare()`（`game/night/NightEvent.java:143-154`）按万分比掷骰，`NoellesRolesConfig.nightEventEnableChance` 默认 `200`（2%）；`/sre:night next` 强制；模式门槛与命令方块相同（`supports()` `:131-136`）；轮抽/志愿模式推迟到选完职业再发装备（`defersEquipment` `:138-141`）。

**流程**（开局一次性切换，整局维持，没有分阶段剧情）：

1. 时间锁午夜：`level.setDayTime(18000)` + `SRETrainWorldComponent.TimeOfDay.MIDNIGHT`，每秒纠偏（`:179-180`、`:219-223`）。
2. 全场永久关灯：`SREWorldBlackoutComponent.startNightEvent()`（`:181`）关掉所有带 `LIT`/`ACTIVE` 的灯并记录原值，禁止中途 `reset()` 复亮（`cca/SREWorldBlackoutComponent.java:63-96, 116-125`）。
3. 视野压到 16 格（`NightRoundState.VIEW_DISTANCE = 16`、`fogStart/fogEnd` `:39-45`，客户端 `WorldRendererMixin:72-76`）。
4. 每人发一把 `noellesroles:flashlight`（`equip()` `:197-210`，满包落地不吞装备）。
5. 死亡原地化 `noellesroles:undead`（`onDeath()` `:236-252`，删真实尸体），警戒 12 格 / 漫游 8 格 / 牵引 20 格（`NightUndeadRules.java:7-10, 38-44`），与亡灵之主的亡灵是独立账本。
6. 结束 `clear()`（`:254-268`）恢复时间与全部灯光、清掉本局亡灵。

**演示分段（建议 4 段）**：`nightfall`（标题 + 副标题 + 灯逐盏熄灭）→ `flashlight`（手电筒开关与光锥、视野 16 格）→ `undead`（玩家死亡 → 亡灵出现并逼近幸存者）→ `restore`（结束恢复灯光与时间）。

**缺口**：夜天与雾无法直接设置；「灯突然全灭」需要逐灯 `set_block` 或新步骤；亡灵 AI 逼近只能用 `role_walk` 代理。不涉及职业改写，是本篇三条里最轻的。

### 10.3 `halloween_event`（万圣节事件）

**触发**：没有概率，唯一门槛是地图配置 `AreasSettings.halloweenEventEnabled`（默认 false）+ `halloweenNpcSpawnPos`（`api/AreasSettings.java:332-340`，中文名「启用万圣节小镇活动」）；运行时判定 `HalloweenRuntime.isMapEnabled()`（`game/halloween/HalloweenRuntime.java:26-31`），`OnGameStarted` 建 session。

**流程**（整局并行的多条子系统，不是线性剧情）：

1. 残月 NPC（`noellesroles:halloween_village_npc`）生成在固定坐标，右键开 `VillageShopScreen`，用南瓜/金币换道具（`game/halloween/HalloweenVillage.java:122-147, 276-314`）。
2. 敲门：潜行空手右键 `SmallDoorBlock`，奖励 60% 1–2 南瓜 / 30% 亡灵 / 10% 糖果袋，另有 20% 冒出发糖残月（`HalloweenVillage.java:215-256`）。
3. 魂契：每 3 个真实任务 20% 掉 `halloween_soul_contract`，靠近残月交付；死亡后复活为中立 `halloween_pact`（不能攻击/用物品/拾取，跟随最近非依附玩家阵营获胜，`HalloweenPactRole.java:38-51`）。
4. 开局把一名杀手改写成 `undead_lord`（`HalloweenRuntime.java:74-82`）。
5. 道具：`halloween_blood_saw`（3 格蓄力）、`halloween_fright_gun`（30 格 + 冻结 + 召唤亡灵）；持有刀具的职业商店可 200 金币买 8 耐久血锯。
6. 万圣亡灵：枪击/敲门/靠近残月击杀生成橙金色 `noellesroles:undead`（`HalloweenCombat.java:349-391`），上限 32。
7. 南瓜精 `pumpkin_spirit`（独立胜利，收集南瓜）与南瓜据点（`minecraft:item_display` + `interaction`，不放方块）。
8. 环境：橙色穹顶/雾/天光/月亮（`game/halloween/ambience/HalloweenAmbienceSky.java:39-54`）+ 音乐 `halloween:music.town`。
9. **亡魂夜（Ghost Night）已移除**，配置字段仅兼容保留、不再读取（`HalloweenVillage.java:118, 172-176`，记录见 `docs/halloween-village.md:58-62`），教程不得演示定时关灯/暗闪/旁观者鬼脸。

**演示分段（建议 5 段）**：`village`（门廊小镇 + 残月与商店）→ `knock`（潜行空手敲门，三档奖励分条标注概率）→ `contract`（魂契交付与复活为 pact）→ `combat`（血锯 / 惊魂枪 → 橙色亡灵）→ `pumpkin`（南瓜精与据点）。

**缺口**：残月商店走 `VillagePackets.Offer`（`HalloweenVillage.java:278-292`），**不是** `ShopEntry` 体系，现有 `role_shop` 读不到，需要新增「残月商店陈列」步骤或降级为文本 + 物品实体；橙色天空无步骤；60/30/10 与 20% 的随机分支不能在同一条时间轴呈现，只能按段落叙述并写明概率。

### 10.4 三条事件的共同难点

1. 世界级状态：服务端写的是 CCA 组件、session tick 与整局开关，Ponder 沙盒里没有真实时间/雾/全局光照，所有环境效果都要靠「新步骤」或「搭场景近似」。
2. 缺环境层步骤：现有 16 个自定义步骤全是职业/覆盖层类，内置步骤也没有时间、天气、天空、雾、全场光照入口；紫天、夜雾、橙天这三个最标志性的观感目前都表达不了。
3. HUD 全是 S2C 包：破坏进度+倒计时、标题/字幕只能用 `role_state` / `role_info` 近似，样式与真实 HUD 不一致。
4. 概率必须显式标注：万分比骰、60/30/10、20% 魂契、池内随机改写，线性时间轴会被误读成「必然发生」。
5. 职业改写最难：异常 → 15 个池内杀手，需要同段落换职业/皮肤/商店 + 顶部字幕；`role_player` 的皮肤在步骤内固定，只能多个 `role_player` + `linkId` 替换展示。
6. 时间轴：事件节奏是 60s / 120s / 75–112.5s，必须用 `idle` 压缩并加注释，否则文本重叠（`PONDERER_SCENE_AUTHORING.md:24-41`）。
7. 无现成结构：命令方块机房/车顶开阔场地、夜间小镇、万圣门廊都要新建 NBT 并跑 `verify_ponder_structures.py`。

### 10.5 事件篇的前置公共能力（先做这些，再写三条场景）

| 能力 | 用途 | 影响范围 |
| --- | --- | --- |
| `role_ambience`（新步骤：天空/雾/天光/时间染色） | 紫天、夜雾、橙天 | 三条事件全部 |
| `role_hud_bars`（双条进度 + 倒计时） | 破坏进度 + 事件倒计时 | `command_block` |
| `role_rewrite`（同段落换职业：皮肤 + 名称 + 商店 + 字幕） | 异常 → 杀手、杀手 → 亡灵之主 | `command_block`、`halloween_event` |
| `role_village_shop`（残月商店陈列，读 `VillagePackets.Offer`） | 南瓜/金币兑换 | `halloween_event` |
| `role_blackout`（逐灯熄灭的批量 `set_block` + 音效） | 灯全灭的瞬变 | `night_event`、`command_block` 关灯事件 |
| 结构：`event_command_room` / `event_night_town` / `event_halloween_porch` | 三条事件各自的舞台 | 三条事件全部 |

建议顺序：先做 `night_event`（只需环境层 + 1 个结构，能顺带验证 `role_ambience`），再做 `halloween_event`（验证 `role_village_shop`），最后做 `command_block`（依赖环境层、双条 HUD 与职业改写三件套都就绪）。

### 10.6 写事件教程前必须先核对的既有文档

- `docs/命令方块杀手事件.md` 与本规划逐条对齐过：`commandBlockEnableChance` 默认值已按源码 `NoellesRolesConfig.commandBlockEnableChance = 1000`（10%）修正，旧值 80 作废。
