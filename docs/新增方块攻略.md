# 新增方块攻略（StarRailExpress / noellesroles）

> 面向「下次要加方块的人类 / AI」的实操攻略：照着抄能跑通，改动集中在少数文件里。
> 配套阅读：`AGENT.md`、`docs/api.md`（API 清单可能过时，以源码为准）。
> 注意区分：`docs/自定义工具文档.md` §四 讲的是**给地图创作者用**的游戏内「自定义方块工具」（`custom_block`），本文讲的是**写代码加方块**。
>
> 本文所有路径都取自本仓库真实代码。主要示例是最近的 `space_air`（太空空气）与既有的 `train_light`、`remote_redstone`、`poison_zone`、`custom_block`。

---

## 0. 四条铁律（先看这里）

1. **逻辑集中在方块类里**：方块行为写在 `content/block/**` 的方块类，注册写在 `index/**`。不要在事件回调里散落一堆 `if (state.is(XXX))`。
2. **事件只注册一次**：需要每 tick 跑的东西，统一挂在既有的 `ServerTickEvents` 回调里遍历/查表；**不要**给每个方块或每个方块实体实例注册事件（`AGENT.md` 明文规定）。"实体进入方块"这类判定用方块自己的 `entityInside` 记录 + 统一结算（见 §5）。
3. **资源手写，不要跑 datagen**：`fabric.mod.json` 里的 `fabric-datagen` 入口还在，但 provider 已被删除；`runDatagen` 会以空产物覆盖**已被 git 跟踪**的 `src/main/generated`（见 §9）。
4. **编码与风格**：UTF-8 **无 BOM**；注释 / Javadoc 用中文；文件头与同目录邻居保持一致（`content/block/**` 下的方块文件普遍带 GPL 文件头）。

## 1. 最短路径：新增一个方块要动哪些文件

| 步骤 | 文件 | 必做 |
| --- | --- | --- |
| ① 方块类 | `src/main/java/io/wifi/starrailexpress/content/block/XxxBlock.java`（主模组）或 `src/main/java/org/agmas/noellesroles/content/block/XxxBlock.java`（扩展侧） | ✅ |
| ② 注册方块 + 物品 + 分页 | `src/main/java/io/wifi/starrailexpress/index/SREBlocks.java`（或同包的 `SREDecorationBlocks` / `SREDoorBlocks` / `SREDisplayBlocks` / `SREFumoBlocks`，扩展侧为 `org/agmas/noellesroles/init/{ModBlocks,ModSceneBlocks,SREFumoBlocks}.java`） | ✅ |
| ③ 方块资源 | `src/main/resources/assets/<ns>/blockstates/<id>.json`、`models/block/<id>.json`、`models/item/<id>.json`、`textures/block/<id>.png`（物品图标：`textures/item/<id>.png`） | ✅ |
| ④ 语言键 | `src/main/resources/assets/starrailexpress/lang/{zh_cn,en_us,zh_tw}.json` → `block.<ns>.<id>` | ✅ |
| ⑤ 战利品表（想掉落才写） | `src/main/resources/data/<ns>/loot_table/blocks/<id>.json` | 按需 |
| ⑥ 渲染层（半透明 / cutout） | `client/model/TMMModelLayers.java`（或 `client/SREClient.java`）：`BlockRenderLayerMap.INSTANCE.putBlock(...)` | 按需 |
| ⑦ 方块实体 | 方块类 + `index/SREBlocks.java` 的 `customBlockEntityRegistrar`（抄 `CUSTOM_BLOCK_ENTITY`） | 按需 |
| ⑧ 让不可见方块在创造模式下能被看到 | `mixin/client/scenery/ClientWorldMixin.java` 的 `MARKER_PARTICLE_ITEMS` | 按需 |
| ⑨ mixin（非必要不写） | 新 mixin 类 **+ 写进** `src/main/resources/starrailexpress.mixins.json` 的 `mixins` / `client` 列表 | 按需 |
| ⑩ 编译 | `./gradlew compileJava`（秒级）/ `./gradlew remapJar`（出成品 jar）。**不要随手 `./gradlew build`**（见 §9） | ✅ |

> 战利品表现状：`starrailexpress` 命名空间下**没有**任何方块战利品表（只有 `trainmurdermystery` 有 158 个，在 `src/main/generated/data/trainmurdermystery/loot_table/`）。也就是说在该命名空间注册的方块**默认破坏不掉落**——想掉落要么手写 loot table，要么接受不掉落（OP / 不可破坏类方块惯例是显式 `.noLootTable()`，需要给物品时在 `playerDestroy` 里自己 `Block.popResource(...)`）。
>
> 目录名注意：1.21 是单数 `loot_table/`、`tags/block/`、`tags/fluid/`、`tags/item/`（写成复数不会被加载，项目里 `data/minecraft/tags/fluids/` 就是踩了这个坑）。

## 2. 注册：三种写法与创造分页

### 2.1 主模组侧的三个 helper

`index/SREBlocks.java` 里已经有现成 helper，**优先用它们**：

```java
// 进 noellesroles:block 分页（绝大多数装饰方块的默认选择）
Block MY_BLOCK = registerBlock("my_block", new MyBlock(properties));
// 同上，另外给物品属性（稀有度、堆叠数、craftRemainder…）
Block MY_BLOCK2 = registerBlock("my_block2", new MyBlock(properties), new Item.Properties().rarity(Rarity.EPIC));
// 进 OP 管理员页 + 场景编辑页（管理员 / 地图制作用）
Block MY_OP_BLOCK = registerOpBlock("my_op_block", new MyBlock(properties), new Item.Properties().rarity(Rarity.EPIC));
// 只注册方块、不给物品（物品另由其它途径提供，例如自定义 BlockItem）
Block NO_ITEM_BLOCK = onlyRegisterBlock(SRE.id("no_item_block"), new MyBlock(properties));
```

底层是 ratatouille 的 `BlockRegistrar`（`SREBlocks.blockRegistrar = new BlockRegistrar(SRE.MOD_ID)`）：

| 重载 | 用途 |
| --- | --- |
| `createWithItem(id, block)` | 自动建 `BlockItem`（默认 `Item.Properties()`） |
| `createWithItem(id, block, itemProps)` | 同上 + 物品属性 |
| `createWithItem(id, block, tabs...)` / `createWithItem(id, block, itemProps, tabs...)` | 注册时直接指定创造分页 |
| `createWithItem(id, block, block -> new MyBlockItem(block, props), tabs...)` | 自定义 `BlockItem` 子类 |

> 用 `createWithItem` 注册的方块，`asItem()` 能正常拿到物品（`TrainLightBlock.getShape`、`ClientWorldMixin` 的 `MARKER_PARTICLE_ITEMS` 都依赖这一点）。**如果**你自己 `Registry.register(BuiltInRegistries.ITEM, ...)` 注册 `BlockItem`，必须补一句 `item.registerBlocks(Item.BY_BLOCK, item)`，否则 `asItem()` 会拿到空气（照抄 `SREBlocks.registerCustomBlockItem()` 与 `SREDecorationBlocks.registerBlockItem()`）。

### 2.2 初始化链（新注册表文件才需要动）

`SRE.initRegistries()`（`SRE.java`）依次调用 `TMMBlocks.initialize()` → 内部再调 `SREBlocks.initialize()` → 最后 `blockRegistrar.registerEntries()` 真正注册。扩展侧在 `Noellesroles` 的初始化里调 `ModBlocks.initialize()` / `ModSceneBlocks.initialize()`。

所以：
- 往**已有**的注册表文件里加方块（最常见）：只写字段即可，`registerEntries()` 会自动收。
- 新建一个「方块族」注册表文件：记得自己写 `initialize()` 并挂进上面那条链。

`initialize()` 里除了 `registerEntries()`，还常做：注册创造分页、注册方块实体类型、注册物品的创造分页条目。

> **字段声明顺序坑**：接口字段按声明顺序初始化，而物品注册可能反过来读其它 index 类的静态字段。`SREBlocks.CUSTOM_BLOCK` 的注释记录了这件事——新方块字段尽量**声明在一堆已有字段之后**，或者放在你确定没有交叉依赖的位置。

### 2.3 创造分页

现成的分页（挑一个塞进去即可）：

| 分页 key | 标题键 | 说明 |
| --- | --- | --- |
| `noellesroles:block`（`ModBlocks.BLOCK_CREATIVE_GROUP`） | `item_group.noellesroles.block` | 普通装饰方块默认去这里 |
| `noellesroles:scene` / `noellesroles:quest` | `item_group.noellesroles.scene` / `...quest` | 场景编辑 / 小游戏任务点 |
| `starrailexpress:theme_decorations` | `item_group.starrailexpress.theme_decorations` | 主题装饰 |
| `CreativeModeTabs.OP_BLOCKS`（原版） | `itemGroup.op`（管理员方块） | OP / 管理员方块 |
| `noellesroles:door`、`starrailexpress:building` / `decoration` / `equipment` 等 | — | 门、建筑、装饰等既有分类 |

要**新开一个分页**（想避免污染既有分页时）：

```java
// 1) 声明 key（建议放在对应 index 类里，如 SREBlocks）
ResourceKey<CreativeModeTab> MY_GROUP = ResourceKey.create(Registries.CREATIVE_MODE_TAB, SRE.id("my_group"));

// 2) 在 initialize() 里注册分页本体（必须在分页被填充之前执行到）
Registry.register(BuiltInRegistries.CREATIVE_MODE_TAB, MY_GROUP, FabricItemGroup.builder()
        .title(Component.translatable("item_group.starrailexpress.my_group"))
        .icon(() -> new ItemStack(MY_BLOCK.asItem()))
        .build());

// 3) 往分页里塞物品（可以塞任意多个不同的 ItemStack）
ItemGroupEvents.modifyEntriesEvent(MY_GROUP).register(entries -> entries.accept(MY_BLOCK.asItem()));
```

完整示例见 `SREBlocks.SPACE_AIR_CREATIVE_GROUP`（含"每个状态一个条目，图标相同、靠 lore 区分"的循环）。

> **坑**：`createWithItem(..., tabs)` 只会把**默认那一个**物品堆塞进分页。想像原版灯方块那样"每个状态一个条目"，必须自己在 `ItemGroupEvents` 里循环 `entries.accept(stack)`（原版参考：`CreativeModeTabs.java` 里 `for (int i = 15; i >= 0; i--) output.accept(LightBlock.setLightOnStack(new ItemStack(Items.LIGHT), i));`）。

### 2.4 命名空间怎么选

| 命名空间 | 谁在用 | 资源目录 |
| --- | --- | --- |
| `starrailexpress`（`SRE.id(...)`，= mod id） | 主模组方块（`SREBlocks`、`SREDecorationBlocks`、新方块推荐） | `src/main/resources/assets/starrailexpress/` |
| `trainmurdermystery`（`SRE.TMM_MOD_ID`） | 历史遗留的旧命名空间（`TMMBlocks`），很多老方块在这里 | `src/main/generated/assets/trainmurdermystery/`（datagen 产物，已提交） |
| `noellesroles`（`Noellesroles.id(...)`） | 扩展侧内容 | `src/main/resources/assets/noellesroles/` |

新方块**优先用 `starrailexpress`**：资源放 `src/main/resources/assets/starrailexpress/`（手写），语言键写成 `block.starrailexpress.<id>`（语言文件是聚合的，键前缀跟着**注册命名空间**走，不是 mod id）。

## 3. 方块类模板（可直接抄）

### 3.1 最小值

```java
public class MyBlock extends Block {
    /** 0..15 的档位示例；不需要状态就整段删掉 */
    public static final IntegerProperty LEVEL = IntegerProperty.create("level", 0, 15);
    /** 1.21 必须有 codec()，抄这一行即可 */
    public static final MapCodec<MyBlock> CODEC = simpleCodec(MyBlock::new);

    public MyBlock(Properties properties) {
        super(properties);
        registerDefaultState(stateDefinition.any().setValue(LEVEL, 0));   // 每个属性都要给默认值
    }

    @Override
    protected MapCodec<? extends Block> codec() {
        return CODEC;
    }

    @Override
    protected void createBlockStateDefinition(StateDefinition.Builder<Block, BlockState> builder) {
        builder.add(LEVEL);
    }
}
```

### 3.2 属性（`Properties`）常用项

| 想要的效果 | 写法 | 备注 |
| --- | --- | --- |
| 玩家能穿过 | `.noCollission()` | 也可在形状里返回 `Shapes.empty()` 保留选中 |
| 不遮挡邻面 / 透明 | `.noOcclusion()` | 透明方块**必须**加，否则周围面被剔除出黑洞 |
| 像空气一样可被放置替换 | `.replaceable()` | 放置时直接覆盖它 |
| 生存不可破坏 + 不掉落（OP 方块惯例） | `.strength(-1.0F, 3600000.8F).noLootTable()` | 创造仍可瞬间破坏 |
| 瞬间破坏 | `.instabreak()` | 装饰小物件 |
| 发光 | `.lightLevel(state -> 15)` 或 `.lightLevel(SimpleTrainLightBlock::lightBlockSupplier...)` | 注意区分：`getLightBlock` 是**挡光**，`lightLevel` 才是发光 |
| 岩浆式光照 + 随机刻 | `.randomTicks().lightLevel(s -> 15)` | 参考 `Blocks.LAVA` |
| 复制原版方块全部属性 | `.ofFullCopy(Blocks.GLASS)` | 想改其中一项时用 `SRE$setCol(false)`（见下） |
| 没有碰撞但保留了 `ofFullCopy(BARRIER)` 的其它属性 | `((BlockSettingsAdditions) Properties.ofFullCopy(Blocks.BARRIER)).SRE$setCol(false)` | `SRE$setCol` 是本模组通过 `fabric.mod.json` 的 `loom:injected_interfaces` 注入到 `BlockBehaviour.Properties` 上的（`util/BlockSettingsAdditions` + `mixin/block/AbstractBlockSettingsMixin`） |
| 活塞行为 | `.pushReaction(PushReaction.DESTROY / BLOCK)` | |
| 音效 / 地图色 | `.sound(SoundType.WOOD)` / `.mapColor(MapColor.NONE)` | |

### 3.3 状态相关（有 `LEVEL`/`FACING` 这类属性时才需要）

- `getStateForPlacement(BlockPlaceContext)`：放置时决定初始状态（朝向、含水、从物品组件读值）。
- `rotate` / `mirror`：`state.setValue(FACING, rotation.rotate(...))`（结构方块 / 旋转用）。
- `neighborChanged`：红石联动（例如 `TrainLightBlock`）。
- `canSurvive → true`：允许悬空放置（列车灯系列全这么干）。
- 含水：`implements SimpleWaterloggedBlock` + `WATERLOGGED` 属性 + `getFluidState` + `updateShape` 里 `scheduleTick`（完整写法抄 `CustomBlock`）。

状态数爆炸的注意点：属性越多，`BlockState` 组合越多（4×2×16… 轻易上千）。blockstate JSON 用**一条通配变体**就能覆盖全部状态（`"": {"model": ...}`），但状态数本身仍会进全局调色板，属性别乱加。

## 4. 不可见方块：三个关键点（都是踩过的坑）

以 `SpaceAirBlock`（太空空气）为例：不可见、无碰撞、不参与交互，只在创造模式手持对应物品时"显形"。

```java
// ① 不渲染几何体（区块网格里不生成面）
@Override
protected RenderShape getRenderShape(BlockState state) {
    return RenderShape.INVISIBLE;
}

// ② 条件形状：默认给空形状 → 射线直接穿过，放置 / 右键 / 破坏都不会命中它；
//    手持本物品或调试棒时才给出形状，于是能选中、能破坏、能用调试棒调档位
@Override
protected VoxelShape getShape(BlockState state, BlockGetter level, BlockPos pos, CollisionContext context) {
    return context.isHoldingItem(this.asItem()) || context.isHoldingItem(Items.DEBUG_STICK)
            ? Shapes.block()
            : Shapes.empty();
}

// ③ 必须显式覆写！默认实现是 `!Block.isShapeFullBlock(getShape(...)) && 空流体`，
//    而上面 getShape 手持时会返回完整方块 → 手持瞬间透光率变化、光照跟着跳一下
@Override
protected boolean propagatesSkylightDown(BlockState state, BlockGetter level, BlockPos pos) {
    return true;
}

@Override
protected int getLightBlock(BlockState state, BlockGetter level, BlockPos pos) {
    return 0;    // 像空气一样不吸收光照
}
```

- **`skipRendering` 别乱抄**：`MirrorBlock` / `LoopingMirrorBlock` 覆写它返回 `true`，但语义（剔除自己还是剔除邻居）在反编译源里无法确认；不可见方块不写它没有任何损失。相邻墙面消失这类诡异 bug 往往就来自这里。
- **`RenderShape.INVISIBLE` 的方块仍然需要 blockstate JSON + 模型**：模型不会被画出来，但**屏障粒子**（见下）用的是 blockstate 模型的 `particle` 贴图。
- **让玩家"看得见"不可见方块**：把物品加进 `ClientLevel.MARKER_PARTICLE_ITEMS`（`ClientWorldMixin`），原版就会在**创造模式 + 主手拿着该物品**时给方块画屏障粒子（`ParticleTypes.BLOCK_MARKER`）。原版判定（`ClientLevel.getMarkerParticleTarget`）要求：创造模式、主手物品、且该物品是 `BlockItem`——三条都满足才有效。项目里 `TrainLightBlock` / `RemoteRedstoneBlock` / `KillBlockPanel` 等 14 个不可见方块都用这招。
- 想让不可见方块在选中时显示**轮廓**而不是粒子：条件 `getShape` 就够（手持物品 / 调试棒才给形状）。

## 5. 区域效果类方块：对实体做点什么

### 5.1 判定"任意部位在方块里" → 覆写 `entityInside`

```java
@Override
protected void entityInside(BlockState state, Level level, BlockPos pos, Entity entity) {
    if (!level.isClientSide && entity instanceof LivingEntity living) {
        MyRuntime.markInside(living, 参数);
    }
    super.entityInside(state, level, pos, entity);
}
```

- 这条路径由原版 `Entity#checkInsideBlocks` 驱动，**按实体碰撞箱覆盖的体素判定**，与方块自身有没有碰撞箱**无关**（下界传送门、气泡柱同样靠它工作）。"任意部位在方块里"天然成立。
- **限制**：`checkInsideBlocks` 由 `Entity.move(...)` 触发，所以**骑乘中的实体不会触发**（原版行为，玩家坐船/坐矿车时流体效果不生效）。
- 不要在这里做重活：它每 tick 对每个重叠实体都会调用一次。

### 5.2 每 tick 统一结算（对属性/效果做增删）

照抄 `SpaceAirGravityRuntime` 这套「双表 + 末端结算」：

```java
private static final ResourceLocation MODIFIER_ID = SRE.id("my_block_speed");   // 独立 id，别复用别人的
private static final Map<UUID, Pending> PENDING = new HashMap<>();  // 本 tick 命中（markInside 写）
private static final Map<UUID, LivingEntity> TRACKED = new HashMap<>();  // 当前挂着 modifier 的实体

// entityInside 里只记录
public static void markInside(LivingEntity entity, float value) { /* 同实体取"效果最强"的一档 */ }

// 每服务端 tick 末统一结算（挂在 SREEventRegister 里那个 ServerTickEvents.END_SERVER_TICK，追加一行）
public static void flush() {
    // 1) 对本 tick 命中的实体：addTransientModifier / 数值变了才重写（避免每 tick 刷属性包）
    // 2) TRACKED 里本 tick 未被刷新的：removeModifier（离开方块 / 方块被拆 / 断线都会走到这里）
    // 3) finally { PENDING.clear(); }  ← 必须清空，否则残留会让实体永久保留效果
}
```

关键约定：

- modifier 用 **transient**（不入存档）：死亡、跨维度、重连后自然失效，下一 tick 若还在方块里会自动重挂，不需要任何持久化。
- modifier id 必须**独立**。地图重力用的是 `SRE.id("map")` + `addOrReplacePermanentModifier`，同 id 会互相覆盖（`GameUtils` 里有"不要修改 base 用 modifier"的警告）。
- 同一 tick 身处多个效果方块时，本项目惯例是**取绝对值最大者**（效果最强者优先）。
- 目标过滤放在 `entityInside` 里（只玩家 / 所有 `LivingEntity` / 什么都不限）。

### 5.3 常用效果的现成写法速查

| 想做的事 | 写法 | 参考位置 |
| --- | --- | --- |
| 阻碍/加速移动 | `Attributes.MOVEMENT_SPEED` + `ADD_MULTIPLIED_TOTAL`（如 `-0.5` = 减速 50%，`-1.0` = 完全不能动） | `PriestHeavenManager`（`addTransientModifier`） |
| 加重/减轻重力、上浮 | `Attributes.GRAVITY` + `ADD_MULTIPLIED_TOTAL`（负值 → 重力为负 → 持续上浮） | `SpaceAirGravityRuntime` |
| 禁止跳跃 | `Attributes.JUMP_STRENGTH` + `-1.0 ADD_MULTIPLIED_TOTAL` | `NRGameStateEvents` 的 `no_jumping` |
| 每 tick 伤害 / 直接致死 | `GameUtils.killPlayer(player, spawnBody, killer, GameConstants.DeathReasons.XXX)`；判死前先 `GameUtils.isPlayerAliveAndSurvival(player)`，并用 `player.hasEffect(ModEffects.SAFE_TIME)` 短路 | `KillBlockPanel`、`SREGameWorldComponent` |
| 施加药水效果 | `player.addEffect(new MobEffectInstance(MobEffects.SLOW_FALLING, 40, 0, false, true, true))`；长时效果用 `ModEffects.of(...)` | `RepairPrimarySkillC2SPacket`、`GameUtils` |
| 免摔落 | 注册 `OnPlayerFallOnGround.EVENT` 返回 `TrueFalseResult.FALSE`（会连原版落地伤害一起取消；该事件目前**无人监听**，是干净扩展点） | `mixin/entity/FallDamageCheckMixin` |
| 溺水 / 免窒息 | `LivingEntity#decreaseAirSupply` 注入点已存在，加分支即可 | `mixin/entity/living/LivingEntityMixin` |
| 进入时执行命令 | 事件系统（进入/离开/停留 + 冷却 + 职业/阵营条件）见 `CustomBlockRuntime` + `CustomBlockData.events` | `customblock/` |

> 上面这些"每 tick 效果"最终都建议走 §5.2 的统一结算，而不是到处 `addEffect` / 直接改 `deltaMovement`。玩家位移是**客户端权威**的，服务端硬推位置会和客户端打架。

## 6. 物品侧：中键拾取保留状态 + lore

### 6.1 中键拾取保留状态（原版灯方块的做法）

```java
@Override
public ItemStack getCloneItemStack(LevelReader level, BlockPos pos, BlockState state) {
    return MyBlock.setLevelOnStack(super.getCloneItemStack(level, pos, state), state.getValue(LEVEL));
}

public static ItemStack setLevelOnStack(ItemStack stack, int level) {
    if (level != DEFAULT_LEVEL) {
        stack.set(DataComponents.BLOCK_STATE, BlockItemStateProperties.EMPTY.with(LEVEL, level));
    }
    return stack;
}
```

- 原版 `BlockItem`（`updateBlockStateFromTag`）在**放置时**会自动把 `BLOCK_STATE` 组件套回方块状态，所以"拾取 → 放下"状态不丢，不需要覆写放置逻辑（对照原版 `LightBlock.setLightOnStack`）。
- 读回来用 `stack.get(DataComponents.BLOCK_STATE)` + `properties.get(LEVEL)`（**可为 null**，注意判空）。

### 6.2 lore / 提示写在方块类里

`BlockItem.appendHoverText` 会把提示转发给方块自己的 `Block.appendHoverText`，所以**不需要**为了 tooltip 写自定义 `BlockItem`：

```java
private static final int TOOLTIP_COLOR = 0x7b9aba;   // 项目统一的方块提示配色

@Override
public void appendHoverText(ItemStack stack, Item.TooltipContext context, List<Component> tooltip, TooltipFlag flag) {
    tooltip.add(Component.translatable("tooltip.starrailexpress.my_block.state", Integer.toString(levelOf(stack)))
            .withColor(TOOLTIP_COLOR));
    super.appendHoverText(stack, context, tooltip, flag);
}
```

- 翻译串里**只用 `%s`**，数字先在代码里格式化（`String.format(Locale.ROOT, ...)`）：不同语言占位符类型不一致会格式化失败。
- 想直接写死多行说明（数据驱动内容那种）也可以用 `DataComponents.LORE` + `new ItemLore(list)`（先 `stack.remove(DataComponents.LORE)` 再 `set`，避免叠加；见 `CustomBlockLoader.applyData`）。
- 物品名替换：`DataComponents.ITEM_NAME`。

### 6.3 什么时候才需要自定义 `BlockItem` 子类

需要覆写放置/使用逻辑（自定义放置校验、右键开界面、把物品数据写进方块实体）时才建，写法照 `customblock/CustomBlockItem` + `SREBlocks.registerCustomBlockItem()`（手工注册物品 + `registerBlocks(Item.BY_BLOCK, item)` + `ItemGroupEvents` 加进分页）。

## 7. 方块实体（需要存数据 / 按配置渲染时才建）

```java
// index/SREBlocks.java：类型用 BlockEntityTypeRegistrar 收集
BlockEntityType<MyBlockEntity> MY_BE = customBlockEntityRegistrar.create("my_block",
        BlockEntityType.Builder.of(MyBlockEntity::new, MY_BLOCK));
```

方块实体类里通常要实现：

| 方法 | 作用 |
| --- | --- |
| `saveAdditional` / `loadAdditional` | 存档（`CompoundTag`） |
| `getUpdateTag` / `getUpdatePacket` | 客户端同步（`ClientboundBlockEntityDataPacket`）；也可自己发 payload |
| `applyImplicitComponents` / `collectImplicitComponents` | **物品 ↔ 方块实体**：放置时从物品组件还原配置、挖掉时把配置写回掉落物（`CustomBlockEntity` 是范本） |
| `setRemoved` / `setLevel` | 注册表索引的增删（`CustomBlockRuntime` 是范本） |

按配置改外观：`CustomBlock` 走的是 `RenderShape.ENTITYBLOCK_ANIMATED` + `BlockEntityRenderer`（模型完全由渲染器画，blockstate 只要一条通配变体），要看外观解析（资源包贴图 / 继承原版方块 / 占位紫黑棋盘）就抄 `CustomBlockAppearance` + `CustomBlockRenderer`；物品侧对应 `CustomBlockItemRenderer`（`BuiltinItemRendererRegistry`）。

需要每 tick 干活时：**不要**给每个 BE 注册事件，用 `BlockEntityTicker`（`getTicker`）或统一挂 `ServerTickEvents` 遍历——项目惯例是后者（`CustomBlockRuntime` / `SpaceAirGravityRuntime`）。

## 8. 资源与语言（手写清单）

### 8.1 最小 JSON

```jsonc
// assets/starrailexpress/blockstates/my_block.json —— 无属性方块
{ "variants": { "": { "model": "starrailexpress:block/my_block" } } }

// 有属性时：单条通配变体覆盖所有状态；也可以像 train_light.json 那样逐状态指定模型
{ "variants": { "level=0": { "model": "starrailexpress:block/my_block_0" },
                "level=1": { "model": "starrailexpress:block/my_block_1" } } }

// models/block/my_block.json
{ "parent": "minecraft:block/cube_all", "textures": { "all": "starrailexpress:block/my_block" } }

// models/item/my_block.json —— 方块物品的图标
{ "parent": "minecraft:item/generated", "textures": { "layer0": "starrailexpress:item/my_block" } }
```

- 贴图 16×16 PNG，放 `textures/block/` 与 `textures/item/`；流动/动画贴图再加同名 `.png.mcmeta`（内容 `{"animation": {}}`，参考 `textures/block/cobblestone_liquid.png.mcmeta`）。
- **可以直接借用现成模型**省掉资源：`minecraft:block/lava`、`minecraft:block/water`、`wathe:block/light_barrier`（`trainmurdermystery` 命名空间的老方块大量这么做）。此时 blockstate JSON 仍然要写。
- 不可见方块也别省 `models/block`：屏障粒子的贴图取自模型的 `particle` 项。

### 8.2 语言键

| 键 | 位置 |
| --- | --- |
| `block.starrailexpress.<id>` | `assets/starrailexpress/lang/{zh_cn,en_us,zh_tw}.json`（zh_cn 是 Crowdin 源，先补它） |
| `item_group.starrailexpress.<分页id>` | 同上（自定义创造分页标题） |
| `tooltip.starrailexpress.<id>.<字段>` | 同上（方块提示；物品提示在物品类的 `appendHoverText` 里引用） |

BlockItem 的显示名走 `block.*` 键（`BlockItem.getDescriptionId()` 返回方块的键），**不需要**再写 `item.*`。

### 8.3 渲染层与交互

- 半透明 / cutout：在客户端初始化里 `BlockRenderLayerMap.INSTANCE.putBlock(block, RenderType.translucent() | cutout())`（现有集中位置：`client/model/TMMModelLayers.java`、`client/SREClient.java`；`TMMModelLayers` 里同时也有 `FluidRenderHandlerRegistry` 的注册）。
- 禁止右键交互（箱子/工作站那种）：把方块 id 加进 `util/CantRightClickBlocks.CANNOT_INTERACT_IDS`（扩展侧统一入口 `org/agmas/noellesroles/utils/RightClickBlockManager.init()`）；生效链路是服务端 `event/PlayerInteractionHandler` + 客户端 `mixin/entity/player/CanRightClickMixin` 两条，所以别只改一边。
- 若要完全"不参与交互"，更简单的是 §4 那个条件 `getShape`（默认空形状），射线根本打不到它。

## 9. 踩坑清单（本仓库真实踩过的）

1. **别跑 `runDatagen`**：`fabric.mod.json` 里的 `fabric-datagen` 入口指向 `io.wifi.starrailexpress.datagen.TMMDatagen`（类已删除），provider 全空；跑起来会用空产物覆盖**已提交**的 `src/main/generated`。
2. **别随手 `./gradlew build`**：`build.finalizedBy(generateSha256)` 会往 `hashes/hash-list.txt` 追加哈希，把 git 工作区弄脏。要成品 jar 用 `./gradlew remapJar`（产物 `build/libs/starrailexpress.jar`）。
3. **`propagatesSkylightDown` 必须显式覆写**（条件形状方块）：默认实现读 `getShape()`，手持物品形状变化会让光照跳变。
4. **`skipRendering` 不要照抄镜子方块**：语义在反编译源里无法确认，不可见方块完全不需要它。
5. **空形状 = 什么都做不了**：破坏、调试棒、中键拾取、放置都要先能"选中"，所以想留后门就"手持特定物品/调试棒时返回 `Shapes.block()`"。
6. **`createWithItem(..., tabs)` 只放一个默认物品堆**：要"每个状态一个条目"得自己循环 `entries.accept(stack)`（原版灯方块写法）。
7. **`Block.asItem()` 依赖 `Item.BY_BLOCK`**：手工注册 `BlockItem` 时必须 `item.registerBlocks(Item.BY_BLOCK, item)`。
8. **`entityInside` 对骑乘实体不触发**（`checkInsideBlocks` 由 `move()` 触发），需要覆盖坐船/坐矿车的场景要另找入口。
9. **modifier id 别撞车**：`SRE.id("map")` 是地图重力（`addOrReplacePermanentModifier`），复用会互相覆盖。
10. **客户端属性包**：每 tick 无条件 `addTransientModifier` 会把属性标脏、白刷同步包；只在"不存在或数值变化"时写。
11. **不可见方块不会自动"可见"**：要让管理员看到它，加 `MARKER_PARTICLE_ITEMS`（原版限定：创造模式 + 主手 + `BlockItem`）。
12. **tag 目录是单数**：`tags/block`、`tags/item`、`tags/fluid`（项目里 `data/minecraft/tags/fluids/` 是复数，实际没被加载）。
13. **语言文件键前缀跟注册命名空间走**：`TMMBlocks` 里注册的方块要写 `block.trainmurdermystery.<id>`，写成 `block.starrailexpress.*` 不生效。
14. **编码**：所有新文件 UTF-8 **无 BOM**（`zh_tw.json` 历史上带 BOM，别照着复制这个特征）。
15. **新增 mixin 必须登记**：写进 `starrailexpress.mixins.json`（或 `noellesroles.mixins.json`）的 `mixins` / `client` 列表，`injectors.defaultRequire = 1`，漏登记不会报错、只是静默不生效。
16. **接口/静态字段初始化顺序**：`SREBlocks` 这类接口按声明顺序初始化字段，跨类的静态引用可能读到 `null`/默认值（见 `CUSTOM_BLOCK` 的注释）。

## 10. 调试 / 自查清单

```bash
./gradlew compileJava        # 秒级，先过这一步
./gradlew remapJar           # 出成品 jar（别用 build，见 §9.2）
./gradlew runClient          # 手测
```

游戏内自查：
1. 创造模式在目标分页里能找到物品（找不到 → 分页没注册 / `ItemGroupEvents` 没挂 / 物品没注册）。
2. 放下后外观、碰撞、发光、含水是否正确。
3. 中键拾取 → 重新放置，状态是否保留（§6.1）。
4. 工具提示是否正常显示、数字是否正确。
5. 破坏是否掉落（`starrailexpress` 命名空间默认不掉落，见 §1 注）。
6. 若有每 tick 逻辑：进入 / 离开 / 方块被拆 / 玩家死亡重生 / 换维度 / 重连后是否都能正确恢复（§5.2 的 `TRACKED` 回收路径）。
7. 装了 Sodium/Iris 的话再确认一遍渲染（管线不同）。

常见现象 → 原因：

| 现象 | 多半是 |
| --- | --- |
| 方块是紫黑棋盘 / 报 missing model | blockstate JSON 缺了或路径写错；`models/block` 缺失 |
| 方块透明但周围一圈是黑洞 | 少了 `.noOcclusion()` |
| 看不见也选不中、破坏不了 | `getShape` 默认返回了空形状（要留后门就加"手持物品/调试棒"分支） |
| 手持物品时世界光照跳一下 | 没显式覆写 `propagatesSkylightDown` |
| 相邻墙面消失 | 抄了 `skipRendering` |
| 物品显示名是 `block.starrailexpress.xxx` 原文 | 语言键没补或命名空间写错 |
| 破坏不掉落 | 该命名空间没有 loot table，且没在 `playerDestroy` 里 `popResource` |
| 属性效果"有时候没了" | 用了 permanent modifier 却没清理，或者 modifier id 撞了地图重力 |

## 11. 一个完整的真实例子：`space_air`（太空空气）

| 文件 | 作用 |
| --- | --- |
| `content/block/SpaceAirBlock.java`（新增） | 方块本体：`gravity` 状态（0..30）、`RenderShape.INVISIBLE`、条件 `getShape`、`propagatesSkylightDown`、`getCloneItemStack`（中键保留档位）、`appendHoverText`（lore）、`entityInside`（记录重力档位） |
| `content/block/SpaceAirGravityRuntime.java`（新增） | 每 tick 结算：PENDING/TRACKED 双表 + `END_SERVER_TICK` 里 `flush()`，`ADD_MULTIPLIED_TOTAL` 的 transient modifier（id `starrailexpress:space_air_gravity`） |
| `index/SREBlocks.java`（改） | `SPACE_AIR` 注册 + `SPACE_AIR_CREATIVE_GROUP` 专用分页 + 31 个档位条目的循环 |
| `register/SREEventRegister.java`（改） | 在既有 `END_SERVER_TICK` 里追加 `SpaceAirGravityRuntime.flush();` |
| `mixin/client/scenery/ClientWorldMixin.java`（改） | `MARKER_PARTICLE_ITEMS.add(SREBlocks.SPACE_AIR.asItem())` —— 创造手持时显形 |
| `assets/starrailexpress/blockstates/space_air.json`、`models/block/space_air.json`、`models/item/space_air.json`（新增） | 三份手写 JSON |
| `assets/starrailexpress/textures/{block,item}/space_air.png`（新增） | 两张 16×16 贴图 |
| `assets/starrailexpress/lang/{zh_cn,en_us,zh_tw}.json`（改） | `block.*` / `item_group.*` / `tooltip.*` 共 4 个键 × 3 语言 |

配套的行为约定（可作为同类"区域效果方块"的参考）：

- 档位换算：`modifier = (gravity - 20) × 0.1`，即 0 → -200%、20 → +0%、30 → +100%；改范围只动 `SpaceAirBlock` 的 `MAX_LEVEL` / `NEUTRAL_LEVEL` / `PERCENT_PER_LEVEL` 三个常量。
- 默认档位 = 无效果，且等于默认档位时**不写** `BLOCK_STATE` 组件（和原版灯方块一致）。
- 生存不可破坏（`strength(-1, 3600000.8)` + `noLootTable()`），创造破坏需先手持物品 / 调试棒让它可被选中。
- 与地图重力叠乘（地图用 `ADD_VALUE`，这里用 `ADD_MULTIPLIED_TOTAL`，互不覆盖）。
