## 实现

### 属性组合的构建期索引

JFR 显示 `StateHolder.populateNeighbours` 在 Handcrafted 等高状态数方块注册时存在大量属性 Map 哈希冲突与比较。

新增 `StateCombinationMap`、`StateDefinitionLookupMixin`：仅在 `StateDefinition` 构造器调用原版 `populateNeighbours` 时，替换其临时查询容器。每个定义建立一次混合进位整数索引，按实际状态对象填充，不依赖状态列表的排列。原版仍负责创建全部状态、决定状态顺序、生成邻接表和执行 `setValue`。

- 最多 262144 个槽位、32 个属性；64 状态及以下沿用原流程。
- 空/重复值域、超预算、非法或重复组合等不能无歧义索引的输入回退原容器；非标准查询键也沿用原 Map 查询。
- 稀疏组合仍返回原本的缺失结果；有效查找保留原状态对象身份。
- 索引只由构造器局部引用持有，不作为游戏全局状态缓存。
- 与已装 ModernFix 的临时状态 Map 配合，不接管它的状态构造补丁，不新增第三方依赖。

运行时 JFR 已记录新索引调用链，未发生每个状态反复重建索引；第一轮 `StateCombinationMap.create` 仅出现 2 个执行采样，而不是用计数推算调用次数或具体省时。

### ArrayTable 不可变布局复用

剩余采样显示原版反复为邻接表构建相同的行/列键索引。新增 `NeighbourTableFactory`、`StateHolderTableMixin`，使用 Guava 官方 ArrayTable 拷贝构造复用空布局模板：

- 返回类型仍为原版 `ArrayTable`；行/列顺序、键对象身份、null 单元格和状态引用保持不变。
- 仅当行/列键的对象身份及顺序完全相同才共享布局；相等但不同的属性或值不会串用。
- 每个表的可写单元格数组独立，修改一个表不影响其他表或模板。
- 仅处理标准非空 HashBasedTable；其他表沿用原始复制行为。
- 最多保留 256 个空模板，每个最多 4096 个单元格，不缓存状态对象或源表。
- 首个主菜单就绪 tick 或客户端停止时清空并停用模板缓存。复用已有生命周期回调，清理不依赖原始类字节缓存是否开启。

- 碰撞哈希、4096 个组合及全部单属性变化、任意状态/属性顺序、稀疏组合、非法键、预算/溢出/歧义回退。

- 布局顺序及键身份、相等但不同对象隔离、可写数组隔离、null/自定义表行为、大布局回退、LRU 上限、清空后不再积累、并发构建。
