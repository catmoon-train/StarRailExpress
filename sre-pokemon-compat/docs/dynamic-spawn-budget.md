# 宝可梦动态刷新预算

## 用户确认的规则

正常负载最高保留原版 40%，随卡顿加重逐步降至 10%；严重时也不因负载主动暂停刷新。恢复后缓慢回升。不清除已有宝可梦，不限制队伍放出，也不修改队伍或 PC 容量。原有 `pokmen=false` 手动关闭仍优先。

本机制替代此前固定 60% 的刷新预算，已有宝可梦 AI 思考降低 70% 的补丁继续生效。

## 负载与预算

读取 MC 1.21.1 自带 `MinecraftServer.getAverageTickTimeNanos()`：最近最多 100 tick 的平均计算耗时，不包含维持目标 TPS 的正常休眠。每 20 个服务端 tick 评估一次，所有维度、玩家共用当前服务端预算，不按玩家重复扫描实体或区块。

| 平均 tick 耗时 | 目标保留比例 |
| --- | ---: |
| ≤40ms | 40% |
| 50ms | 35% |
| 70ms | 25% |
| 90ms | 15% |
| ≥100ms | 10% |

40–100ms 之间线性计算。目标下降时在下一次评估直接下调；目标持续高于当前预算 5 个评估窗口（100 tick）后，最多回升 2 个百分点，然后重新累计恢复窗口。负载再次恶化会清空恢复计数。

正常 20 TPS 时约每秒评估一次、持续改善五秒后恢复一步；从 10% 完全恢复到 40% 至少需要约 75 秒，另受平均耗时窗口影响。低 TPS 下这些实际等待时间会相应延长。运行时预算始终处于 10%–40%，不累积补刷欠账。

## 作用范围

同一预算分别作用于：

- `PlayerSpawner.tick` 的自然刷新计时推进倍率：预算越小，尝试间隔越长。
- `Spawner.calculateSpawnActionsForArea` 的有效密度上限：仍在全局/局部 `pokemonPerChunk` 取较大值后缩放，避免另一项绕过预算。

不对单次生成量再随机抽样，不改变生成区域、物种权重、稀有度、存储或玩家放出队伍的路径。频率和密度分别缩放，不能把保留比例直接解释为实际新增数量或整服 TPS 收益。

“不暂停”是指负载控制不会把预算降至零，也不会因卡顿拦截已排队动作。原版生成条件、密度上限和手动关闭仍有效：附近数量已超过新上限时，会等数量自然下降后再允许刷新，并不保证每次尝试一定生成。

新增 common `main` 入口仅在安装 Cobblemon 时注册服务端 tick 及启动/停止事件。无客户端类引用；专用服及内置服务器均适用。连接远程服务器的客户端不会替远程服务端采样。启动/停止时重置预算和恢复计数，不跨单人存档遗留压力；无 Cobblemon 时不注册采样事件。

## 验证与更新

运行 `./gradlew :sre-pack-compat:test :sre-pack-compat:remapJar --offline --console=plain` 成功。兼容包共 276 项测试，0 失败、错误、跳过；本轮新增 13 项，覆盖目标曲线、20 tick 评估、严重负载不暂停、慢恢复、反复卡顿、上下限、重置、异常样本、动态预算与原手动开关及 common 入口注册。

正式 JAR 已确认包含新入口、控制器；平均耗时方法映射为生产 `MinecraftServer.method_54834()`，没有测试类。构建仍有此前已有的 `ModelBakery.addExtraModel` 映射提示，不影响成功打包。

产物：`sre-pack-compat/build/libs/sre-pack-compat-1.0.0.jar`。停止服务器，备份并替换旧兼容 JAR，再重启即可；不需要额外命令。没有改版本、增加依赖、修改服务器配置或自动部署到运行实例。

未运行真实服启动、长期多人负载或同场景 TPS 对比。动态预算不负责清除已有实体、修复区块压力或 GC 停顿，实际改善仍需部署后复采验证。
